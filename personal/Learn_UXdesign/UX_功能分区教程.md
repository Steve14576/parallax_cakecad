## 〇、一个真实事故：为什么「排布」值得单独学

2007 年，微软把 Office 用了二十年的下拉菜单换成了 **Ribbon**（中文叫「功能区」，就是你打开 Word 时顶部那一排带图标的选项卡组）。这是界面史上最大规模的公开实验，结果两极：新用户上手速度显著提升，老用户则爆发了近乎愤怒的抵制，微软收到的投诉信是历史级的。

同一个界面，一半人说「终于不用在八层菜单里挖了」，一半人说「我闭着眼都能找到的东西现在找不到了」。这说明一件事：

**功能区排布不是美术问题，是「把功能映射到空间」的决策问题。** 每个决策都有真实代价，代价由人的认知规律决定，不由设计师的个人品味决定。这份教程讲的就是这些规律和代价。

## 一、问题的本质：界面是一张「物理地图」

### 1.1 用户脑子里存的是位置，不是逻辑

先用大白话说清一个认知事实：人找东西有两种方式——

- **回忆（recall）**：从记忆里把东西「调出来」。比如问你「文件菜单下第三个子菜单叫什么」，你得使劲想。
- **识别（recognition）**：东西摆在眼前，你认出来。比如给你一张菜单截图，你一眼就能看到「打印」在哪。

识别比回忆轻松一个数量级——这是认知心理学几十年的稳定结论。界面设计的第一个推论随之而来：

> **好的布局让用户「认」，坏的布局让用户「想」。**

而「认」依赖空间记忆。你用久了任何一个软件，记住的都不是「文件 → 导出 → 导出为 PNG 这个逻辑路径」，而是「那个按钮在右上角偏下一点」这种**物理位置感**。这就是为什么软件改版的最大风险不是功能增减，而是**挪动位置**——你挪走的不是像素，是用户练了几百小时的空间记忆。

**心智模型**：把界面想象成一座城市的地图。功能就是建筑。市民（用户）靠肌肉记忆走街串巷。你可以盖新楼（加功能），可以拆危房（删功能），但把市中心搬去郊区（重排核心区），全城通勤都会瘫痪。

**这条规律什么时候用**：每次你想「把这个按钮挪个位置」时，先问：有多少用户已经对它形成空间记忆？改动收益够不够赔？（后文 Blender 案例 7.4 会看到这条规律被正反两面验证。）

### 1.2 屏幕空间是稀缺资源，排布就是资源分配

界面设计的第二个本质：**所有「可见」的位置加起来是固定的**（就那么大一块屏幕），而功能只会越来越多。所以排布问题永远是分配问题——给了 A 就亏待了 B。于是产生一切布局设计的根本张力：

> **可发现性（discoverability）vs 屏幕空间（screen real estate）。**

先把这两个词说清楚，后面反复用：

- **可发现性**：一个功能「被新用户注意到、找到」的容易程度。摆在明面上 = 可发现性高；藏进三层菜单 = 可发现性低。
- **屏幕空间**：界面里能显示东西的总面积。对创作软件尤其要命——画布/文档区是用户真正干活的地方，工具栏每多吃一寸，画布就少一寸。

两个方向打架：想让功能好找，就得摆出来；摆出来的东西多了，画布没了。整个教程的方法论，本质都是在这条张力上找平衡点。记住这对矛盾，后面每个案例都是它的某个解法。

### 1.3 本教程的分析工具：四个判据

后面拆每个案例，都用同一把尺子。这四条现在先给出，**理解到「会拿它审界面」的程度就够**，不用背：

| 判据 | 一句话 | 反例长什么样 |
|---|---|---|
| **① 频率原则** | 高频功能占好位置，低频功能让边 | 把「修改许可证」和「保存」摆在一起 |
| **② 就近原则** | 操作对象的东西，挨着对象摆 | 调图层透明度的面板离图层预览十万八千里 |
| **③ 分组原则** | 同类功能聚在一起，异类分开 | 「复制图层」混进了字体设置组里 |
| **④ 逃生原则** | 任何藏起来的功能，必须有一条「搜索直达」的后门 | 功能藏进三级菜单，还没有任何办法搜到它 |

「好位置」指什么，这里一次说全，因为后面每条都依赖它：

- **屏幕四角四边**：窗口边缘是「无限大」的点击目标——鼠标往边缘一甩就命中，不用瞄准。这背后有条定量规律叫 **Fitts 定律**（Fitts's Law）：**点到目标所需时间 ≈ 距离越远越慢、目标越小越慢**。推论：边角的大按钮是全屏幕最容易点中的东西，四个角又是边角中最容易到达的。
- **顶部**：视线第一落点，适合放「身份性、全局性」的东西。
- **右侧**：右手鼠标用户的顺侧（界面惯例默认右利手），适合放「对当前选中物做精调」的东西。
- **常驻可见**：不需要任何点击就看得见 = 位置里的顶级奢侈品。

> **一个新词当场解释**：上面说的「好找程度」有个专门的学术名字叫 **Affordance**（示能/可供性），指一个界面元素「看起来就能被那样用」的程度——按钮看起来能按、滑杆看起来能拖。本教程只在需要你评价「这个控件用户会不会注意到」时提它一次，**知道有这回事就够**，不影响后面阅读。

## 二、通用地图：屏幕分区的基本语法

这一节给你一张「界面语法表」——桌面软件和移动软件各自约定俗成的分区槽位。**这不是某家公司的规定，是几十年演化沉淀下来的行业默认值**，你自己做软件时，先照着这个语法填，再谈创新。

### 2.1 桌面应用的五带结构

绝大多数桌面应用（尤其创作类），都可以拆成五条带：

```
┌────────────────────────────────────────────┐
│ ① 标题栏 / 菜单栏：身份 + 全局命令            │
├────────────────────────────────────────────┤
│ ② 工具条带：常用动作的快捷入口                 │
├──────┬─────────────────────────┬───────────┤
│      │                         │           │
│ ③ 左 │      ⑤ 中央工作区        │ ④ 右侧    │
│ 导航 │      （画布/文档）        │  属性区    │
│ 区   │                         │           │
│      │                         │           │
├──────┴─────────────────────────┴───────────┤
│ （可选）状态栏：反馈与模式指示                  │
└────────────────────────────────────────────┘
```

五个槽位的分工，每个配一句「为什么是它」：

| 槽位 | 放什么 | 为什么是这个位置 |
|---|---|---|
| ① 菜单栏 | 全局命令：文件操作、偏好设置、帮助 | 全软件唯一「保证存在」的条，用户找不到东西时最后一眼看的地方 |
| ② 工具条 | 高频动作的图标快捷方式 | 紧贴工作区上方，点一下就到，省得开菜单 |
| ③ 左导航 | 「项目里有什么」：文件树、图层列表、素材库 | 阅读习惯从左到右，先看「有什么」再看「长什么样」 |
| ④ 右属性 | 「选中的东西能调什么」：参数面板 | 选完对象后右手顺势右移调参，动线最短 |
| ⑤ 中央 | 真正干活的画布/文档 | 必须拿到最大面积——这是创作软件的命根子 |

**这张表要理解到什么程度**：要能拿着它对着自己软件的界面逐个槽位打勾——「我的左侧放的是不是'有什么'？右侧放的是不是'能调什么'？」。左右放反了（属性在左、导航在右）不是非法，但你在跟全行业的肌肉记忆作对，得有足够理由。

### 2.2 三个必须当场解释的子形态

五带结构里藏着三种反复出现的子形态，后文案例全是它们的变体，现在一次讲透：

**（a）停靠面板（Dockable Panel）**：能拖动、能吸附在窗口边缘、能叠成选项卡、能拖出去变浮动窗的小面板。Photoshop 是它的祖宗（案例 7.2 细拆）。它解决的是「专业用户要同时开很多面板，但屏幕装不下」——所以面板要能**收纳（折叠成一条）**、能**重组（按自己的习惯拖放）**。

**（b）选项卡组（Tab Group）**：多个面板共用一块地盘，用顶部的选项卡切换。本质是「同一块屏幕空间在不同时刻显示不同内容」，是省空间的主力手段。代价：切走的选项卡**暂时不可见**，可发现性下降——所以选项卡的排列顺序本身就是一种排序决策（高频组放最左）。

**（c）检查器（Inspector）**：右侧属性区的专业叫法。特征：**它的内容随你的选中物实时变化**——选中文字它显示字体，选中矩形它显示圆角。理解方式：检查器是一面「当前选中物的镜子」，不是一个固定的设置页。

### 2.3 移动端三槽位（对照用，简短）

手机上没有鼠标也没有大空间，语法完全不同，这里给个速记版（**建立直觉就够**，除非你要做移动端）：

```
┌─────────────────┐
│ ① 顶部：页面标题  │
│   + 本页关键动作   │
├─────────────────┤
│                 │
│ ② 中央：内容流   │
│                 │
├─────────────────┤
│ ③ 底部标签栏：    │
│  3~5 个一级分区   │
└─────────────────┘
```

核心差异：桌面靠「分区常驻」，移动靠「层级钻取」——一级页面只露 3~5 个入口（底部标签栏），其余功能放进下一层页面。原因很直白：屏幕就这么大，摆不下，只能**用时间换空间**（多点一下，换一屏的干净）。案例 7.6 的微信会把这点用到极致。

## 三、理论地基：为什么这样排是「对」的

第二节给了「大家长什么样」，这一节给「为什么」。四条理论，每条都给：它说什么 + 对布局的具体推论 + 什么时候用得上。

### 3.1 Fitts 定律：点击成本是会算出来的

**它说什么**：移动到目标并按下的时间，随「距离变远、目标变小」而增加。不用记公式，记住三个推论：

1. **边角无限大**：鼠标甩到屏幕边缘会停住，所以贴着边缘的控件等效尺寸巨大，是最好点的位置。这就是为什么 macOS 的菜单栏贴在屏幕最顶端（苹果菜单贴顶，闭眼甩上去就中），也解释第一节末尾那句「四角四边是好位置」。
2. **大按钮配高频动作**：保存按钮给 8×8 像素的小图标，等于给最高频的动作征收最重的点击税。
3. **挨着放省路程**：「经常连着用的两个控件」要贴在一起——选中图层后马上要调透明度，这两个动作之间的鼠标路程就是每日重复几百次的浪费。

**什么时候用**：审任何一个按钮的「大小 × 位置」时。有个专门的名词叫**点击税**：用户每执行一次操作付出的移动+瞄准成本。高频动作收重税，是布局的头号罪行。

### 3.2 KLM：一次操作是有「秒数」的

**KLM**（Keystroke-Level Model，击键层级模型）：一种把界面操作拆成基本动作、给每个动作计时的估算方法。它给每个动作标了经验耗时——移动鼠标到目标约 1.1 秒、点一下约 0.2 秒、按一个键约 0.1~0.3 秒、脑子切换一次任务模式约 1.35 秒。

**你不需要会算它**（理解深度：知道有这回事 + 需要精确对比方案时去查）。它真正要给你的只有一句话：

> **菜单深度是明码标价的**。一个藏在「菜单 → 子菜单 → 子子菜单」里的命令，每次使用 = 三次瞄准点击 + 若干秒，而且每层菜单展开都在收「脑子切换」那笔最贵的税。

这直接推出**频率原则的定量版**：日付百次的操作必须常驻可见；月付一次的操作进三级菜单天经地义。Office Ribbon 改革的正当性就来自这笔账（案例 7.1）。

### 3.3 组块（Chunking）：人一次只能记住 4±1 样东西

**它说什么**：工作记忆（你脑子里同时端着的临时托盘）容量极小，现代研究的估算是 **4 个上下浮动 1 个**组块。你常听到的「7±2」是老教材数字，现在普遍收紧到 4±1，但对本教程结论没影响——反正很小。

**对布局的推论**：

1. **一个工具栏超过 ~7 个并列图标，就开始被用户「视而不见」**——眼睛会自动跳过超出托盘的部分。解法不是删功能，是**分组**：用分隔线把 20 个图标切成 4~5 簇，每簇内部再按逻辑排。人看「簇」比看「散件」省托盘。
2. **菜单同理**：一个下拉里 30 个平铺命令 = 灾难；切成「文件类 / 编辑类 / 导出类」几段，每段 5 个以内，就能用。
3. **分区的数量也要数**：界面上同时向用户吆喝的「一级区域」别超过 4~5 个。Photoshop 的面板再多，也收纳成四条停靠栏；VS Code 左侧活动栏常年只有 5~7 个图标（案例 7.5）。

**什么时候用**：每次你往一条栏里塞新东西时，数一数塞完后这一栏有几个并列单元。超了，就分组或收纳，而不是硬塞。

### 3.4 渐进披露（Progressive Disclosure）：分层，而不是取舍

**它说什么**：界面只在「当前需要」的层次显示对应内容，深层功能藏在下层入口后面。这是第二节那个根本张力（可发现性 vs 空间）的**标准答案**——不是二选一，是分层：

```
第 0 层：画布上直接可见      ← 每时每刻都在的（画笔、移动）
第 1 层：一次点击展开        ← 工具条旁的下拉、折叠面板
第 2 层：明确去找才有        ← 菜单栏、设置页
第 3 层：主动搜索才到        ← 命令面板（7.5 讲）
```

**关键心智模型**：渐进披露不是「藏」，是**给每层装一个明确的入口标志**。第 1 层的东西必须让人看出「这里点开还有」——一个 ▶、一个 ⋯、一条折叠把手。藏起来但没有入口标志 = 活埋，活埋的功能等于不存在。这条边界就是「渐进披露」和「藏污纳垢」的分界线。

**什么时候用**：给功能表排序时，每个功能问一句「它配第几层？」——判定标准就是频率原则 + 危险度（破坏性操作宁可多一层确认，这是拿披露换安全，值得）。

## 四、案例拉片一：Office——菜单到功能区的革命与反噬

**为什么第一个拆它**：这是「重新排布一切」代价最大的公开案例，正反面教材都齐了。

### 4.1 老世界：下拉菜单时代

1990~2003 的 Office 长这样：

```
┌──────────────────────────────────────┐
│ 文件  编辑  视图  插入  格式  工具 ... │  ← 菜单栏：8~9 个下拉
├──────────────────────────────────────┤
│ [B][I][U]  [对齐▼]  [字号▼] ...      │  ← 工具条：少数高频项
├──────────────────────────────────────┤
│           文档正文                    │
└──────────────────────────────────────┘
```

**这个布局的内在逻辑**：菜单栏是「功能的图书馆索引」——按词性分类（文件/编辑/视图...），全量收录，保证「任何命令都能在菜单里找到」。工具条是「高频快捷通道」，只收十几个最常用的。

### 4.2 拉片：这个布局坏在哪

按第三节的尺子逐条量，旧菜单的死因是三条叠加：

1. **深度税**：功能年年加，菜单只增不减，到 2003 年 Word 的「格式」菜单已经套了三四层子菜单。找一个命令 = 开菜单 → 扫视 → 开子菜单 → 再扫视，KLM 意义上的重税（3.2）。
2. **分类逻辑和用户任务错位**：菜单按「这个命令属于什么词性」分类（编辑类、格式类），但用户干活时想的是「我要给这段字加粗」。动词分类和任务分类是两套坐标系——用户要翻译一遍，这一遍翻译就是每次使用时的认知税。
3. **组块崩溃**：一个下拉里平铺 30+ 命令，超过 4±1 一大截，扫视成本爆炸（3.3）。

同时期微软做了件关键的事：**埋点统计用户实际在用什么**。结论是——绝大多数用户日复一日只用十来个命令，而这十来个命令散落在八层菜单深处。**高频动作付着最深的深度税**，这是频率原则的全面违反。

### 4.3 解法：Ribbon 的构造

2007 的解法就是现在你看到的 Ribbon：

```
┌──────────────────────────────────────────────────┐
│ 开始 | 插入 | 设计 | 布局 | 引用 | ... ← 选项卡组  │
├──────────────────────────────────────────────────┤
│ [剪贴板簇]  [字体簇]  [段落簇]  [样式簇]            │
│  粘贴 加粗  居中▾  行距▾  标题1  ← 每簇3~8个控件   │
└──────────────────────────────────────────────────┘
```

**逐块分析它解决了什么**：

- **选项卡按任务切，不按词性切**：「插入」选项卡收的全是「插入 XX」这个动作家族的东西（表格、图片、页眉）。用户想「我要插图」，选项卡名字和脑子里的动词直接对上，翻译税取消。这是**分组原则的任务坐标系版本**。
- **每簇带文字标签，不再是纯图标**：可发现性拉满——所有命令平铺可见，扫视代替钻取。这是拿**屏幕空间换可发现性**的极端化执行。
- **上下文选项卡（Contextual Tabs）**：选中表格才冒出「表格设计」选项卡，选中图片才冒出「图片格式」——**功能跟着当前对象出现**，这是渐进披露的聪明用法：第 0 层只显示和当前任务相关的东西。

### 4.4 反噬：老用户为什么愤怒

用 1.1 的空间记忆理论看，抵制的原因清清楚楚：

- 老用户存的是**旧地图**：「加粗在格式菜单第二层」。Ribbon 把建筑全搬了，全城通勤瘫痪。
- 更微妙的是**专家退化**：老用户靠纯键盘菜单流（Alt+F→O→B）操作如飞，Ribbon 让这套肌肉记忆作废，却只给了部分新快捷键——**给专家的快捷通道被拆了，换成了对新手的平坦大道**。

**教训（这条进铁律）**：重排布局时，**高频用户的老路径要么保留（兼容模式/旧快捷键），要么提前预告并给迁移指南**。微软后来在 Office 里长期保留「经典菜单插件生态」作为逃生舱，就是在还这笔债。

## 五、案例拉片二：Photoshop——停靠面板体系的极致

**为什么拆它**：创作软件「面板最多、专业最深」的样本，你将来做 CAD 类工具，面板系统几乎必抄它。

### 5.1 总体地图

```
┌────────────────────────────────────────────────────┐
│ 菜单栏：文件 编辑 图像 图层 选择 滤镜 ...              │
├────────────────────────────────────────────────────┤
│ 选项栏：当前工具的参数（画笔画刷大小/容差...随工具变）   │
├──┬────────────────────────────────────┬────────────┤
│工│                                    │ 图层面板    │
│具│                                    │ 通道面板    │
│栏│           画布（中央工作区）          │ 颜色面板    │
│ │                                    │ 属性面板    │
│左│                                    │ （右侧停靠栈）│
├──┴────────────────────────────────────┴────────────┤
```

四个观察点，逐个拉：

### 5.2 左工具栏：动词的清单

左边那一竖条全是**动作**：移动、选区、画笔、文字、裁剪……它回答的问题是「我接下来要**干**什么」。排列逻辑按使用阶段走：选区类在上（先圈范围）→ 绘制类居中（主要工作）→ 辅助类在下（取色、注释）。这就是 2.1 里「左导航」槽位在创作软件里的变体：**左栏放动词（做什么动作），右栏放名词属性（选中物怎么调）**。

### 5.3 顶部选项栏：被低估的天才设计

工具栏正下方有一条**随当前工具变化**的横条：选了画笔，它显示笔刷大小/流量；选了魔棒，它显示容差。

**这解决的是什么**：工具的参数如果塞进菜单，每次调参 = 一次深度钻取；如果全摆在界面上，几十个工具的参数一起露出会淹没画布。选项栏的答案是**第 0 层的渐进披露**：只显示「当前这把工具」的参数，画布几乎不损失，调参零钻取。**上下文相关显示**这个思想，比它出现的年代领先了很多年（7.5 的 VS Code 也在用）。

### 5.4 右侧停靠栈：名词的家

右侧是面板的**停靠栈**：图层、通道、颜色、属性，纵向叠放，每条可折叠、可拖出浮动、可重新拖回吸附。逐条说它为什么这样：

- **图层面板为什么是面板之王**：图层是 PS 的**核心抽象**（每张图 = 一叠透明玻璃片，每片画一点）。一切编辑都在回答「动哪一片」——所以图层列表必须常驻可见，它是操作对象的总目录。这是**就近原则**的极端版：对象目录不在旁边，任何操作都无从谈起。
- **为什么停靠、可折叠、可浮动**：专业用户要同时盯五六个面板，笔记本屏幕放不下。停靠栈的答案 = 用户自定义收纳秩序：常用的拉成常驻，偶尔用的折叠成一条把手，要双屏的拖出去放第二块屏。**把收纳决策权交给用户**，软件只定语法不规定摆设。
- **面板选项卡化**：同一块地里「颜色/色板/样式」共用一个选项卡位——空间不够时的标准省地手段（2.2b），代价是切走的暂时不可见。

### 5.5 这套体系贵在哪、什么时候别抄

**成本**：停靠面板系统的**学习曲线是陡的**——新用户第一次打开 PS，看到三十几个可拖动的面板把手，组块直接爆炸（3.3）。PS 的对策是给**工作区预设**（「摄影」「绘画」几套官方收纳方案），让用户先跑在预设上，再慢慢自定。

**什么时候别抄**：你的软件如果面板总数 < 5 个、目标用户不是每天泡 8 小时的专业人士，别上全套停靠系统——固定几块面板写死位置，比可拖拽便宜得多。**可定制性本身是有成本的，按专业深度付费。**

## 六、方法论：从功能清单到布局成品的五条工序

前面给了「别人长什么样」和「为什么」，这一节给「你自己怎么做」。五条工序按顺序执行，每条都是可操作的动词。

### 6.1 工序一：列「动词-对象」清单（功能盘点）

把软件的所有功能写成**动宾短语**，不写模块名：

```
不是：「图层模块」「导出模块」
而是：新建图层 / 合并图层 / 调整图层透明度 / 导出 PNG / 撤销上一步
```

**为什么必须动宾**：模块名是开发视角（代码怎么分家），动宾短语是用户视角（用户一次按下按钮时在干什么）。切功能区要用用户视角——这是整道工序里最容易被跳过、又最致命的一步。

### 6.2 工序二：标频率和破坏性

给每条动宾短语打两个标：

| 标记 | 分档 | 决定什么 |
|---|---|---|
| 频率 | 高频（天付几十次）/ 中频 / 低频（月付） | 第几层披露（3.4）：高频第 0 层常驻，低频第 2、3 层 |
| 破坏性 | 可撤销 / 不可撤销 | 不可撤销的无论多高频，加确认层或放离常用动线远的位置——防误触 |

打完标，你的清单自然分成三堆：**常驻区候选、折叠区候选、菜单/搜索区候选**。这就是渐进披露分层的直接输入。

### 6.3 工序三：选切分坐标系——整份教程的十字路口

功能怎么归组，有三种切法，**这是布局决策里最大的岔路口**，逐个说清：

**切法 A：按对象切（名词坐标系）**
每个功能区域服务一种对象：「图层区」「文字区」「色彩区」。
- 优点：稳定。对象不随任务变，用户学一次地图一直有效。
- 适合：对象种类清晰、每类对象有自己一堆参数的软件（PS 面板栈、CAD 的属性页）。

**切法 B：按任务阶段切（动词流程坐标系）**
区域按工作流先后排：「建模 → 材质 → 渲染 → 输出」。
- 优点：顺着阶段走，界面自己提示「下一步该干什么」。
- 适合：线性流程强的软件（视频剪辑的「导入→剪辑→导出」、3D 软件的工作区）。

**切法 C：按工具切（器械坐标系）**
一个区域就是一把工具的全部家当：每把工具的参数、预设挤在一起。
- 优点：工具切换成本最低（换工具=换整个上下文，一次到位）。
- 缺点：工具间的共性参数会重复出现。

**怎么选**：问一句「用户的日常工作更像**照看几类东西**，还是更像**走一条流水线**？」前者选 A，后者选 B，靠几把重型器械干活选 C。**混用是常态**（PS = A 为主、C 为辅；Blender 2.8 = B 为主、A 为辅，见 7.4），但**必须有一个主坐标系**——两套坐标系平权，用户就得自己翻译，翻译税回来（4.2 的死因）。

### 6.4 工序四：选布局骨架

切完组，把组摆进 2.1 的五带骨架。桌面创作软件的默认答案：

```
高频动作 → 左竖栏或顶部工具条（Fitts 边角红利，3.1）
选中物参数 → 右侧检查器（就近原则，随选中物变，2.2c）
对象总目录 → 左侧面板（图层/文件/素材）
一切低频全局命令 → 菜单栏 + 命令面板搜索（逃生原则）
破坏性操作 → 不进第 0 层（6.2 的标记）
```

摆完自查一遍四个判据（1.3）：高频的在好位置吗？调参数的紧挨着对象预览吗？同组的聚一起了吗？藏起来的都搜得到吗？

### 6.5 工序五：灰度走查，不动代码

布局画成灰度线框（不上色、不写代码），然后做两个实验：

1. **新手走查**：找一个没见过的任务（「把第二层的不透明度改成 40% 再导出」），让完全没接触过的人只凭线框说「你会点哪里」。说不出 = 可发现性失败，改到能说出。
2. **老手动线计数**：把最常用的 10 个任务写下来，数每个任务的「点击数 + 鼠标路程」。任何日付百次的任务超过 3 次点击，都值得问：能不能提层？

这两个实验不需要软件做完——**这正是你要的解耦**：线框阶段就能跑，等功能实现完了再跑就晚了（改布局的成本随代码量指数增长）。

## 七、案例拉片三：更多样本（按教训分，各取一块）

前面两个案例拆了全套，下面五个各拆一个最有价值的切面。

### 7.1 Blender 2.8 重设计：数据驱动的菜单重组

**背景**：2018 年前的 Blender 是出了名的难学——功能藏在层层嵌套的快捷键和右键菜单里。2.8 版重做了一切。值得拉的是它的**决策过程**，不只是结果：

1. **先埋点，后动手**：团队统计了旧版里每个命令的真实使用频率，发现长尾极长——几百个命令里，90% 的使用量集中在几十个上。**频率数据直接决定了新菜单的层级**（6.2 的工序，用真实数据执行）。
2. **工作区预设（B 切法）**：Layout / Modeling / Sculpting / Rendering 几个工作区，每个是「按任务阶段」的一整套界面——同一块屏幕，在不同阶段显示不同的面板布局。这是 6.3 切法 B 的教科书实现。
3. **右键改左键**：跟随全行业惯例，放弃了自己坚持二十年的右键选择。这是「跟行业语法走还是跟自己的传统走」的取舍——他们选了前者，因为新用户成本大于老用户迁移成本。

**反面验证 1.1**：2.8 同样遭遇老用户抵制（旧快捷键全废）。Blender 的还债方式是官方出了完整的**新旧对照迁移文档**。和 Office 的教训（4.4）互相印证：**重排必赔空间记忆的账，问题只是怎么赔**。

### 7.2 Figma：属性检查器作为一等公民

Figma（网页版界面设计工具）值得拉的是右半边：

```
┌──┬──────────────────────────┬─────────────┐
│图│                          │ 设计 | 原型   │ ← 顶部页签
│层│         画布              ├─────────────┤
│树│    （多人实时协作）         │ 对齐  填充   │
│  │                          │ 描边  效果   │ ← 检查器：
│  │                          │ 文字  布局   │   随选中物变
└──┴──────────────────────────┴─────────────┘
```

- **检查器按属性类别分段**（对齐/填充/描边/效果…），每段可折叠——这是 3.3 组块原则的执行：不把所有参数平铺，切成段。
- **最妙的是「设计 | 原型」页签**：同一个文件，设计模式和原型演示模式共用画布，但右侧检查器内容完全不同。这是**模式（mode）**切分的样本：一个软件里几种根本不同的工作状态，用顶层页签隔开，而不是塞进同一个菜单。**模式之间要隔离得清清楚楚**，不然用户会分不清「我现在处于哪个模式」——模式混淆是 bug 之母。

### 7.3 VS Code：命令面板是终极逃生舱

VS Code 左侧有一条竖栏（**活动栏**：文件/搜索/源代码管理/调试/扩展，常年 5~7 个图标——3.3 组块上限的活样本），点它展开对应侧边栏。值得单拆的是 **命令面板**（Ctrl/Cmd+Shift+P）：

- 一个输入框，**全软件所有命令可搜索直达**——不管这个命令在界面上藏得多深。
- 这就是 1.3 逃生原则的完整实现：**可以藏，但必须留搜索后门**。藏 + 可搜 = 渐进披露；藏 + 不可搜 = 活埋（3.4 的边界）。
- 附带红利：新手不用学菜单结构，老手全程键盘不碰鼠标——**搜索把「回忆坐标」换成了「识别匹配」**（1.1），是空间记忆的替代品而非敌人。

**结论**：你的软件只要有菜单层级，就值得做一个命令面板。它是布局犯错时的保险丝。

### 7.4 微信：极简的反面参照

微信是另一个极端：主界面就三个底部标签（微信/通讯录/我），99% 的功能在二级以下。这不是偷懒，是**面对十亿级异质用户的设计决策**：

- 用户跨度从 8 岁到 80 岁，任何「专业布局」都会压垮低端用户——所以主层极简到只剩内容流 + 入口。
- 但注意**它没有牺牲逃生通道**：顶部全局搜索能搜到任何功能、联系人、聊天记录。越极简的界面，搜索越要做粗——这是 7.3 的同一条铁律在移动端的投影。

**对你（桌面创作工具）的启示是反向的**：你的用户是每天干 8 小时的专业人士，不是十亿路人。微信式的极简会逼专业人士天天钻三层菜单，等于对高频用户征深度税。**极简是给「偶尔用」的人的；专业工具的正道是密度 + 秩序**。别把消费级美学错当成普世答案。

### 7.5 汇总：一张「谁解决了什么」的对照表

| 案例 | 核心矛盾 | 它的解法 | 可迁移到你项目的手段 |
|---|---|---|---|
| Office | 高频动作埋在深菜单 | 按任务切选项卡 + 平铺可见 | 动词坐标系切分（6.3-B） |
| Photoshop | 面板太多屏幕不够 | 停靠栈 + 用户自定收纳 | 可折叠停靠面板（若面板>5） |
| Blender 2.8 | 长尾命令淹没高频 | 埋点定层级 + 工作区预设 | 用频率数据排菜单 |
| Figma | 参数多且随对象变 | 分段折叠检查器 + 模式页签 | 右侧检查器按类别分段 |
| VS Code | 深层命令找不着 | 命令面板全量可搜 | 搜索后门（逃生原则） |
| 微信 | 用户异质极大 | 主层极简 + 全局搜索 | 反面教材：专业工具勿抄 |

## 八、铁律清单：直接拿去审你项目的布局

浓缩成七条，每条都能当打勾项用：

1. **高频占好位**：天付几十次的动作，必须在第 0 层（可见、一键达）。审法：列出你的 10 个最高频动作，逐个看它们现在的位置配不配。
2. **调参数的挨着对象**：属性面板和它作用的对象预览之间，不许隔着别的区域。
3. **左导航右属性是行业默认**：想反着摆，先写下理由。
4. **一个栏里的并列单元 ≤ 7**：超了就分组加分隔线，组内再按逻辑排（组块，3.3）。
5. **可以藏，必须能搜**：任何第 2 层以下的功能，命令面板/搜索必须直达（逃生原则）。
6. **不可撤销的永远多一层**：破坏性操作加确认或挪出热区，这是拿披露换安全，不亏。
7. **重排必赔账**：改老用户习惯了的布局，要么留兼容路径，要么给迁移文档（Office/Blender 双案例，4.4/7.1）。

额外一条元规则：**先抄后改是正当工程方法，不是丢人**。上面六个案例就是给你抄的模板库——选定最像你软件的那个骨架（CAD/创作类大概率是 PS 或 Figma 的骨架），照着填自己的功能，再用铁律 1~6 审一遍。

## 九、回到 CakeCAD：你大概会怎么用这份东西

**这一节不是知识，是应用示范**——拿上面工序，对「蛋糕造型 CAD」这类工具走一遍：

1. **6.1 盘点**：先写动宾清单（「绘制侧面轮廓」「旋转预览」「标注尺寸」「导出加工图」……）。
2. **6.3 选坐标系**：造型类工具大概率是 **A（按对象）为主 + B（造型→标注→输出）为辅**——因为用户大部分时间在照看「这一个造型」，而不是一路走流水线。
3. **6.4 摆骨架**：左竖栏放绘制/编辑动词，右检查器放选中图元的参数（尺寸、圆角、材质），左侧面板放造型的组成部分目录（类似图层树），菜单栏只留文件级命令。
4. **7.3 保险丝**：命令面板先排上，布局没排好的地方它兜底。
5. **6.5 现在就做**：功能还没写完，正好——线框走查现在就能跑，等代码写完再改布局就是 4.4 那种赔账现场。

**A. 拉片练习**（练四个判据，1.3）

验证：随机抽 3 条高频的，看它们能不能全部落进第 0/1 层；任何一条标了「不可撤销」却没进确认层的，回去改。

<details><summary>参考答案（打勾清单形式）</summary>

验收条件逐条打勾即通过：
1. 15 条全部是「动词+对象」形式（如「导出加工图」），没有一条是模块名（如「导出模块」）→ §6.1。
2. 每条都有频率档（高频/中频/低频）和破坏性标（可撤销/不可撤销）→ §6.2。

4. 所有「不可撤销」条目（如「删除整个造型」「覆盖保存」）要么带确认层，要么不在高频动线上 → 铁律 6。

**C. 坐标系判断**（练 6.3）
判断以下软件的主切分坐标系（A 对象 / B 任务阶段 / C 工具）：视频剪辑软件、记事本、3D 建模软件。
验证：答案依据是「用户更像照看几类东西还是走流水线」这句判据（6.3 末尾），不是凭感觉。

<details><summary>参考答案</summary>

- **视频剪辑软件：B（任务阶段）**。用户走「导入 → 剪辑 → 调色 → 导出」流水线，界面按阶段分区（素材库/时间线/导出页）。
- **记事本：都谈不上**。只有一个对象（文档）一条动作流，功能少到不需要切坐标系——硬套 A/B/C 是过度设计。
- **3D 建模软件：B 为主、A 为辅**（同 Blender 2.8，§7.1）：工作区按阶段切（建模/雕刻/渲染），每个工作区内部面板按对象切（场景树/材质/变换）。
判分点：每答一个都要能复述「照看东西还是走流水线」这个判据，说不出判据就算没掌握。
</details>

**D. 综合：给你自己的项目画一版布局线框**（练 6.4~6.5 + 铁律八条）
要求：五带骨架齐全、标注每个区放什么、附一句主坐标系理由。
验证：拿第八章七条铁律逐条打勾，任何一条不过就在图上标出「待改」并写理由。

<details><summary>参考答案（骨架模板 + 打勾清单）</summary>

线框骨架照 §6.4 / §九 的默认答案填：左竖栏=绘制/编辑动词；右检查器=选中图元参数（尺寸/圆角/材质），按属性类别分段可折叠（§7.2）；左面板=造型组成部分目录；菜单栏=仅文件级低频命令；另配命令面板兜底（§7.3）。
主坐标系理由一句话：造型类工具「照看一个造型」的时间远多于「走流水线」，故选 A 为主（§6.3 判据 + §九.2）。
铁律打勾清单（§八）：① 高频动作全在第 0 层；② 参数区挨着画布；③ 左导航右属性；④ 每栏并列单元 ≤7；⑤ 第 2 层以下全部可搜；⑥ 不可撤销操作有确认层；⑦ 若参考了现有用户的旧布局，注明哪些位置动了并给出迁移说明。七条全勾 = 本题通过。
</details>
