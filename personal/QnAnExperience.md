# QnAnExperience

> 一些知识性问题与具体工程问题的追问和答疑，它们流落在原始上下文中比较零散，甚至仍未成型，现在沉淀。一般都是追加式，当然也不排除删改。
> 不同条目具体地分点，一定要分点。且这是用户的追问和答疑，不是agent的默认的过程记录册。
> 此文档的定位就是卡片笔记，适当的也要引原文出处(如果有的话)。但是也不要怕单个点写长，如果它本身就值得详细讲的话。此文档可以应对"不知道自己不知道什么"的问题，通过用户自己问，或者从实践中意识到的，明确或有待发掘的好问题，对它们尽可能见一个记一个。
>
> - 知识性的内容全都是事实性的没有太多依赖问题，追加式。不要官腔，面向给用户的，怎么清楚怎么讲。
> - 工程性内容可能有返工但是一般不直接覆盖，所以要写清楚前提条件，删改也要写清楚当时是为什么现在是为什么，有点像ADR的意思但是没那么官腔和死板格式与行业黑话，否则用户看不懂。这条适用于当这个项目是具体的工程项目。如果这是学习项目，那反正，思路也能借鉴。
>

## 2026-08-31 一批：三处立场更正 + 记忆治理 + 竞品盘点（CakeCAD 调研会话）

背景：这几条都发生在 deep research 调研完成之后。前提先说清楚：**CakeCAD 目前处于前期头脑风暴阶段，连 PRD 都还没定**，所以下面所有"拍板"只表示用户在对话中明确表过的态，不等于项目定稿决策。

### Q1. "我从来没说过可以不做节点图"——为什么之前的报告和记忆都写成了"刻意不做节点图"？

- **当时为什么那样**：coffeehour 原始聊天（主要是 chat1）里有一段"保护底牌"的斟酌——用户有两张未公开的长线底牌（讲解引擎、可执行节点图谱），当时担心黑客松作品撞到底牌语义。agent 读聊天时把这段**斟酌期的自我审查**误当成了设计决策，写进了调研报告第 4.7 节（"为什么不做通用节点图"）。
- **现在为什么改了**：用户明确拍板——"不刻意做"和"刻意不做"完全是两回事；项目已经垂直得足够、不再 meta，底牌斟酌作废；刻意避开节点图会让项目很难做，因为过程 DAG 本身就是一张图。
- **改成了什么**：问题从"做不做"变成"怎么做"——表层是直接操纵，节点图作为过程 DAG 的深层视图按需展开；图的编辑能力用现成框架（React Flow / LiteGraph）不自研。教训取自 Houdini vs Blender 对比：别把节点图做成唯一入口，而不是别做节点图。报告 4.7 节已重写。
- **出处**：`file_researches/deepresearches/instance1/DEEP_RESEARCH_CakeCAD_Platform_Foundation.md` 第 4.7 节；原始材料 [69][70][71]。

### Q2. "我什么时候说过这是 python 路线了？"——技术栈误读事件。

- **当时为什么那样**：仓库现状是 Python 3.12 + uv（hello world 骨架），agent 把仓库现状误读成产品选型，加上调研发现 Python 几何栈（build123d/OCP）成熟，报告 3.5 节写成了"倾向 Python 主体"。
- **现在为什么改了**：用户明确：仓库里的 Python 是**自用的和给 AI agent 用的**（文件管理、离线校验、科学计算），打包时甚至不进；项目主体早就说了用 JS/TS 生态（chat4 主线里定的）。
- **改成了什么**：报告 3.5 节重写为"项目主体走 JS/TS（Three.js + manifold + opencascade.js/occt-import-js + Tauri），Python 仅工具链不进产品"，并标注此为用户拍板、覆盖此前基于材料的倾向。语言中立原则保留（命令日志是 JSON、DAG 定义是文本）。
- **教训**：仓库脚手架的语言 ≠ 产品的技术栈，两个问题要分开问。

### Q3. "把记忆全都读一遍，里面有拍板的所有决策给我看一遍"——记忆审计发现了什么？

- **发现**：9 条记忆里有 3 条是**擅自吸收**的"项目架构决策"——从 coffeehour 原始聊天（2.5 万行、跳脱、可能有前后冲突）里直接提炼升格成"已定架构"写进了记忆：①CakeCAD核心架构（含未经确认的状态机、四层分离、"哲学契约"）；②领域模型语义与懒仿真框架（与①大面积重复）；③功能架构与系统责任边界（CAD/PLM/CAE/CAM 四象限划分、模块通信规则）。
- **为什么这是埋雷**：原始聊天是头脑风暴素材，不是决策记录；AI 提炼时把自己理解的某一个版本当成了定论，用户毫不知情；且"先提一嘴有误导性的东西、再啰嗦解释否定"的表述习惯会加重误导。
- **处理结果**：3 条全删；另立一条纪律记忆（见 Q4）。

### Q4. "我们现在连 PRD 都没确定，你这个会话是纯粹查资料调研的"——调研会话的定位和边界。

- **定位**：调研会话只提供**全面客观分析**（选项、权衡、证据、先例），解耦项目具体架构，不替项目做决策——"要的是全面客观分析，不是全面的擅自干涉"。
- **记忆收录边界**（已写进长期记忆）：只收两类——用户明确拍板的决策/偏好；可核实的仓库与环境事实。原始聊天里的设计倾向一律视为未验证候选，未经拍板不进记忆、不当定论引用。
- **读报告的姿势**：报告里凡是"裁决/倾向/应当"（除用户亲口拍板的 JS/TS 和节点图两处），都读作"有证据支撑的候选项"，不是定论。
- **出处**：`file_researches/deepresearches/instance1/` 主报告 + SUBAGENT_A~H 原始报告。

### Q5. "现在有类似 CakeCAD 的现成工具吗？"（知识性，事实盘点，详细版）

**直接答案**：完全对口（时间轴驱动的物质过程 CAD/PLM + 懒仿真 + 版本化）的工具一个都没有；但把 CakeCAD 拆开看，每个能力维度都有"做了一半"的工具。出处：调研第 2 章，16 个来源交叉验证，引文核验 10/10 通过；方括号编号指主报告 Bibliography。

#### 1. 配方数学/仿真计算（静态，无时间轴）——付费意愿的硬证据

- **BeerSmith [16]**（家酿啤酒）：经营 20+ 年，BeerSmith 4 已发布；桌面买断 + Web + 移动；站内 210 万+ 用户配方；仿真 ABV（酒精体积分数，"这酒多少度"）、IBU（国际苦度单位）、色度、水化学；核心卖点 "scale any recipe to match your equipment in minutes"——同一张配方从 10 升锅换算到 40 升设备、原料量与工艺参数联动重算，本质是 CakeCAD 参数化的缩水版，但只在配方总量层面、不进过程内部；配论坛、300+ 期播客、教程体系。**缺**：无过程时间轴，发酵只是静态参数，不能回滚、不能分叉、不能问"这一步换掉会怎样"。
- **Brewfather / Brewer's Friend [17]**：同赛道订阅制竞品；支持"目标配方反推"——先定苦度和酒精度，倒推投料方案。意义：同一利基里存在多个长期竞争者，订阅制被用户接受，市场容得下几家。
- **gelato 三件套 [18][19][20]**：Gelatodemy（面向职业 gelato 师，年费约 €144、促销 €97，自动算 PAC/抗冻力、POD/相对甜度、固形物/脂肪/糖，口号 "Stop improvising"）；icecreamcalc.app（freemium，社区配方约 1.8 万份——实时浮动计数，核验时 18,392，这个数字本身就是证据：用户愿意把配方资产沉淀在计算器平台上）；Scuola Gelato（冰淇淋学校出品）。结论：窄到"冰淇淋混合料平衡"这一个计算就能养活三家互不相干的厂商；但全部止步于一次性求解，没有"改一步、看全程"。
- **烘焙端 [21]**：工具最高形态就是 baker's percentage（烘焙百分比：以面粉为 100% 基准的配比记法，天然适合缩放）换算与缩放。负结果：按线索检索 Fourish、BakeStreet、Crumb 均无有效结果——**截至核验时，公开网络上找不到任何带发酵模拟或热过程模拟的专业烘焙软件**。烘焙是数学最重的一支（水合率、发酵时间温度、烘烤温度曲线全是变量），工具却停在换算器——付费证据带上最大的缺口开在这里。
- **ChefSteps [89][90][91][92]**：分子料理时代代表，创始人出身 Modernist Cuisine 团队；订阅制（免费层 + $69/年 Studio Pass），付费层含 "370+ 指南、工具和计算器" 与原料缩放工具，另有 Joule 低温慢煮硬件联动。但商业创伤明显：曾濒临破产、被家电厂商 Breville 收购救活——这个品类能活但活得很脆。配套两个事实：Modernist Cuisine 官网搜 "calculator" 零结果（负发现，公开网络端无其工具）；sousvidetools.com 这类第三方时温计算器至今活跃——时温计算已彻底商品化、免费化。**启示：单点计算卖不出钱，不能当卖点。**

#### 2. 能力清单最接近的：工业巨兽与价格断层 [26][27]

- **SuperPro Designer**（Intelligen）：工业批次过程仿真标杆——140+ 单元操作模型（单元操作：工业界把流程拆成的标准积木，加热/混合/过滤/灭菌/冷冻，每块是一个数学模型）、物料与能量衡算、批次调度甘特图、产能瓶颈分析、资源随时间跟踪、工艺经济学；官方行业列表明确含 **Food**。能力清单几乎就是 CakeCAD 的工业镜像。
- **价格断层**：买断 $15,950/拷贝、租赁 $6,380/拷贝/年；欧洲食品学术网络课程页给出简化版锚点：SuperPro LT $1,000、SchedulePro LT $900——连学生简化版都四位数美元。从 €97 的冰淇淋计算器到 $6,380 的 SuperPro，中间相差约 65 倍、空无一物；且它的界面与抽象是给化工工程师的。它证明"过程仿真"本身值钱；它的价格与形态证明这笔钱没法用现有产品形态从小体量食品生产者手里赚到。

#### 3. 时间-温度历史（方向反着：记录而非仿真）[28][29][15]

- **SmartKitchen [28]** 等数字 HACCP（HACCP：危害分析与关键控制点，食品安全体系，找出流程里哪步会出事然后死盯并留记录）：温度监测、留样、报警、云端报表，按许可证收费。它的时间轴是纯记录型、合规型，不可编辑、不可仿真、不可分叉——付钱不是为把菜做得更好，是为向检查员证明"我做对了"。但付费意愿实打实：厨房运营者已习惯为"以时间为轴的记录"按月付订阅费。
- **Galley XAI [29]**：航空配餐，配方级成本与生产排程，"配方级成本可见性直接挂钩真实航班需求"（明天飞 30 班每班 180 份餐，倒推今天备多少料）。
- **Jelly [15]**：英国餐饮成本管理，自动处理供应商发票、实时维护食材成本/配方/毛利；同类还有 MarginPro、Recipe Costing。
- **三家合起来的结论**：商用厨房软件中段全部在做"钱"和"合规"，没一家做"物理"。反读是需求证据：钱包是打开的、订阅制是既有习惯；而且 SmartKitchen 的时间-温度记录与 CakeCAD 的时间轴语义同构——一个记录"实际发生了什么"，一个模拟"应该发生什么、改一步会发生什么"，同一批客户、同一种时间语义、方向从记录翻成仿真。

#### 4. 概念先行者：想法都出现过，但都停在半路 [22][23][24][25][30]

- **Cooklang [22]**：走得最远的一个——开源配方标记语言，把菜谱写成结构化 .cook 文本；官方博客直接教用 Git 管配方、强调 "diff 真的有用"与协作。这是"git for recipes"实践最成形的先行者。但只管版本：配方是静态文本，无过程、无时间、无仿真——停在"数据之上还能跑什么"之前。
- **MIT Media Lab Computational Food [23]**：把食物当"可变形"的可编程介质做交互实验；"食物即程序"在学术层面被探索过，无产品落地（页面抓取超时，据检索摘要）。
- **Bagler 计算美食学 [24]**：直接给学科下定义"让食物可计算"（风味网络、营养、健康与环境的规则化理解），配套论文《Computational gastronomy: A data science approach to food》。学术谱系，不是竞品；提供的是合法性：这条路线不是拍脑袋想出来的。
- **Cakenote [25]**：现存最接近"蛋糕设计软件"的产品：2D/3D/AI 设计，"边设计边看成本和建议售价联动更新"，再接订单管理。证明"设计即时反馈"有人买单；但没有工艺过程：无时间轴、无步骤、无"奶油打发 8 分钟和 10 分钟差在哪"。它站在几何层，CakeCAD 要去的是时间层。
- **Quantz 个人博客《The Protocol of Taste》[30]**：用分布式系统类比拆解烹饪过程，明确提出配方版本控制/回滚（"analogous to software version control—git for recipes"）——说明"过程可回滚"这个概念在独立开发者圈自发冒出来过，不只一家想到；但它是博客不是产品。
- **共同模式**：都停在"把配方写成文本/数据"。从"记录版本"到"仿真过程"那一步，没有一个人跨过去。

#### 5. LLM 时代：消费端商品化，B2B 端真威胁 [80]–[88]

- **消费端已商品化**：Samsung Food [80][81]（2023-08 发布，前身是被三星收购的 Whisk：食谱发现/购物清单/备餐计划/创作者社区；官方口径 AI 个性化 + 家电联动，2024 加视觉识别）——始终是"生成+推荐"范式，无任何过程语义。市场报告量化了这个品类：AI 食品配方软件 19.5% CAGR [86]、Recipe Generation AI $1.8B→$8.7B [87]（聚合商数字，方向性参考）。学术界同样：ACM 2025 论文 [88] 仍是文本+视觉预览范式。那个赛道卖"今天吃什么"，与 CakeCAD 的"这个过程为什么成立"正交。
- **NotCo Giuseppe [82][83][84]**：B2B 端唯一真威胁——辅助食品科学家/主厨的端到端配方优化系统，牛津学术期刊综述确认它处理成本/风味/可得性/可持续/采购约束等数千变量的**约束满足式优化**（真数学，非文本生成）；与 Kraft Heinz 成立合资、为 Magnum 提供端到端创新——大企业付费落地是真的。战场在**配方优化**层（"配方取哪组值最好"），没有时间轴/回滚/擦洗/分叉；但它是名单上唯一有能力从配方层向过程层顺流而下的玩家——哪天它开始输出工艺曲线而不只是配料表，就是最危险的那个。
- **iFactory [85]**：术语重叠度最高的单页产品——AI 重构建模（如减钠 30% 的感官预测）、实验室→量产放大计算（热传导/粘度/混合时间）、替代配料预测（带置信度评分）、"协作工作区 + 版本控制保证可追溯"。但：未见于主流科技媒体，营销页数字未核实——只当竞争信号不当权威。意义：CakeCAD 看中的空地至少已有一支队伍踩过点。
- **未核实清单（对外引用前应补检）**：ChefGPT、RecipeIQ、Platejoy、Foodpairing、YC 系食品 AI 的逐项现状；gPROMS、Aspen、COMSOL 的食品应用未专项检索。

#### 6. 结论：空档的精确画像与它的另一种读法

- 空档是一个精确的矩形：横轴是能力——左边单点计算（BeerSmith 的 ABV/IBU、gelato 的 PAC/POD、烘焙百分比），右边全过程仿真（SuperPro 140+ 单元操作）；纵轴是价格——€97–144/年 ↔ $6,380/年。缺在中间的是：**定价几十到几百美元、能把过程表示成时间上的演化、可回滚可擦洗可分叉、懒仿真（只在有证据处局部求解并标证据等级）、面向中小食品生产者和严肃爱好者的工具**。
- 四组证据：①付费意愿真实（BeerSmith、gelato 三家、ChefSteps、SmartKitchen）；②概念多次自发出现（Cooklang、Quantz、MIT、Bagler）；③过程仿真这道坎无人跨过（Cakenote 有设计无过程、iFactory 有过程但可信度待验、SuperPro 有全套但只属于化工厂）；④LLM 威胁与过程层正交（唯一做真优化的 Giuseppe 停在配方层）。
- **关键提醒（别只记前半句）**："交集为空"有两种解释——没人想到的机会，或没人要的东西。调研区分不了这两种解释，只能靠真人验证（找 3-5 个法甜/entremet 研发者）。这是报告的明确边界。
