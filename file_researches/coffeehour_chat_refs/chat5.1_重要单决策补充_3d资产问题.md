# 一、为什么 dummy 资产 + 语义标注反而更强

你之前的焦虑一直是“3D 资产怎么办”——厨师机建模很怪、照片贴图廉价、每个新物体都要造资产。现在你发现了解法：

> **3D 场景退化为“空间索引的索引”：它的唯一职责是回答“什么东西在哪里、和谁相邻、在哪个容器里”。**
>
> **全部工艺语义走标注层。**

这其实有几个坚实的先例支撑：

1. **化学绘图的球棍模型**——分子不是真的长这样，但它精确表达了连接关系，没人抱怨“原子没有真实质感”；
2. **Blender 的 outliner / 层级视图**——专业 3D 用户大量时间其实在纯文本树里工作；
3. **Beaker/Chemist 这类化学沙盒**——烧瓶就是一个符号，价值在反应语义；
4. **Factorio / Oxygen Not Included 的管道视图**——设备就是色块，流体和逻辑才是主角；
5. **Git 的 DAG 视图**——没有人给 commit 建 3D 模型，但那是最强的“过程信念感”界面。

你的 hover 文字属于第六种：**语义先行渲染**。场景里的一切几何都是代理物（proxy），真实对象是它携带的语义。

# 三、hover 标签需要一个语法：它是“对象的传记”

那条标签之所以有强信念感，是因为它不是属性列表，而是**一段浓缩传记**：

```text
❌ 属性式：type=tart_shell, trimmed=true, forked=true, angle=15°
✅ 传记式："以一个特定角度贴合派盘且用刀修过边并用叉子叉过洞的塔皮"
```

传记式的信息排列有历史顺序（贴合→修边→叉洞）、有方式（特定角度、刀、叉子）、有身份（塔皮）。这正好是你们之前定的事件链的自然语言投影：

```text
Event 1: dough conforms_to pie_dish (angle: specific)
Event 2: knife cut_against pie_dish_boundary
Event 3: fork pierce(dough, bottom_region)
        ↓ 聚合
"以一个特定角度贴合派盘且用刀修过边并用叉子叉过洞的塔皮"
```

所以技术上这不需要奇迹：**对象标签 = 其事件历史的一次 agent 生成摘要**。事件链是你们本来就有的数据结构，现在它成了唯一的“渲染源”。

分级也可以很自然：

```text
Level 0：hover 传记（默认）
Level 1：点开看事件时间线（结构化）
Level 2：点开看原始 Markdown 片段和测量
Level 3：进入算例详情
```

# 四、但要警惕一个反噬：dummy 不能全靠手写

“牛来”的信念感来自**人精心写的文字**。如果每个对象的历史摘要都靠用户手打，操作税又回来了。所以：

```text
传记生成 = agent 从事件链自动摘要
用户只负责：事件链本身（可以一句话建立）
```

用户说“把面皮贴进派盘，沿边修掉，底下叉几个洞”，agent 生成三个事件，hover 摘要自动成立。人写的口语是素材，系统生成的传记是显示。这和你们“原文保留、投影分层”的原则完全一致。

另外 dummy 也要有几个固定的视觉语法，不能全是灰色方块：

```text
形状语法：容器=开口盒、流体=填充高度的盒、粉体=锥堆、工具=杆/片、设备=大块
颜色语法：物料=暖色、工具=冷色、stub=虚线描边、孤儿对象=红色角标
标注语法：浮动文字、锁点=黄点、断点=红点、过期=灰点
```

这些是语义的视觉编码，不是资产——一次性做好，万物通用。

# 五、“牛来”的另一个启示：信念感来自一致性，不来自精细度

电影/游戏里有一个事实：低多边形但物理和逻辑完全自洽的世界，比高精度但穿帮的世界更有沉浸感。你的 dummy 方案同理——

用户会相信这个系统，不是因为烧杯好看，而是因为：

```text
hover 说修过边 → 时间轴上真的有 cut 事件 → 点开真的有 18g 边角料对象 → 它真的出现在冷区对象库里
```

**四处皆一致，信念感自生。** 反过来，只要有一处穿帮（标签说修过边，但事件链里没有 cut），信念感瞬间归零。所以 dummy 方案的最大工程风险不是建模，而是**摘要与事实的同步纪律**——传记必须永远从事件链生成，绝不允许手写覆盖后不同步。

```text

├── hover 传记：agent 从事件链生成（唯一渲染源）

└── 分支：普通分支，事后打标
```

演示的“牛来时刻”可以这样设计：评委看到一个空荡荡、全是几何体和文字的场景，鼠标随意挪过几个东西，读到越来越离谱但自洽的传记（“被蒸汽穿过二十分钟的水和柠檬皮混合物，曾在导流管里短暂成为雾”），然后点开任何一个，看到它的事件链、来源批次、时间和测量全部对得上——**这一刻他们明白屏幕上的每个方块都是一个真实的、被记录的存在**。

这比一个精致的 3D 蛋糕更有辨识度，因为精致会被预期，而“简陋中透出的严谨”会被记住。

你之前说“CakeCAD 太重了，换掉的是离线尊严”——dummy 方案恰好把重量砍掉了大半，而离线尊严大部分回来了：dummy 原语、事件链、轨道、传记缓存都可以本地确定性运行，agent 只负责摘要生成和算例编译，断网时退化为手写标签，项目不死。

# 一、为什么便签沙盒恰好是对的

## 1. 它诚实

精致渲染会撒谎：一个高精度塔皮模型宣称"我知道它长这样"，但系统其实不知道。一张写着"修过边、叉过洞的塔皮"的便签只宣称"我知道这些"——**便签的信息量和系统的真实知识量完全对齐**。这就是信念感的来源：不多说一个字，说的每个字都能点开验证。

## 2. 它降低了用户的完美主义压力

这是你们"自由地摆、诚实地记"哲学的视觉版。用户看到精致 UI 会不自觉地想把数据也填精致；看到便签会自然接受"先潦草写一下"。**便签美学在心理上授权了草稿态。**"适量""差不多""回头再说"写在便签上毫无违和，写在工程软件的参数框里就像个错误。

## 3. 它有现成的视觉词汇，而且全是你需要的

便签文化自带一整套语义标记，恰好映射你们的系统概念：

```text
便签本身        = 对象/事件卡
不同颜色便签    = 物料/工具/设备/介质/stub
歪斜的角度      = 草稿态、未提交
图钉/贴牢       = 已提交、锁点
红笔圈出        = 冲突、守恒差异
铅笔浅字        = 推测、agent 建议
钢笔深字        = 用户确认、实测
划掉重写        = 版本覆盖（划掉的还在！= 历史不删除）
便签叠便签      = 容器内容、组合对象
细绳连图钉      = 物料流、来源绑定（侦探板！）
褪色发黄        = 过期结果
撕掉一角        = 报废/降级物料
```

最后注意"划掉重写"——便签美学里**历史天然可见**，划掉的字还在纸上。这正是你们"历史不重写"原则的视觉化，白送的。

## 4. "侦探板"就是你们的 PLM 视图

细绳连图钉的 conspiracy board 是大众完全看得懂的"溯源图"视觉语言。一个成品蛋糕的便签，几根线拉到面糊、黄油批次、烤箱事件——不需要教用户什么是 PLM，他们看一眼就懂"这东西从哪来"。**你们最难解释的功能，用了最不需要解释的视觉。**

# 四、两个要守住的纪律

## 1. 便签是投影，不是画布涂鸦

风险：用户以为便签是自由涂鸦层，随手改字。必须守住——**便签正文 = 事件链的生成摘要，用户改的是事件和原文，不是渲染结果**。可以允许用户在便签上"追加批注"（那是新的 Note 事件），但不能直接篡改传记正文，否则一致性崩塌，信念感归零。

## 2. 潦草是风格，不是精度声明的缺失

便签上"约630g"的"约"字必须真的对应数据层的 `uncertainty` 或 `qualitative` 标记。风格潦草、数据严谨——反差就是产品魅力；如果数据也潦草，那就真成涂鸦板了。

# 一、先看清你真正想要什么

你的月饼案例从头到尾其实是这样的：

```text
在 Rhino 里拉了个花边圆柱和变形球
→ 它是漂亮的、定制的、有形态学价值的
→ 然后说"这是月饼"
→ 再逆向补上游
```

注意：**你从来没有想给"面糊搅拌到第 3 分钟的样子"建模。** 你在乎形态的地方只有几个：

```text
月饼的花纹和切面
定制蛋糕的分层剖面
编织派皮的顶面
拉糖的造型
```

而不在乎形态的地方占 95%：

```text
碗里的面糊、厨师机、烤箱、
中间状态的面团、蒸馏瓶里的液体……
```

所以问题从来不是"要不要形态学"，而是：

> **形态学是稀疏的。只有少数对象、在少数时刻、值得拥有具体几何。**

这和你们整个系统的哲学完全同构——还记得吗：

```text
语义：默认宽松，需要时严格
仿真：默认休眠，提问时编译
物性：默认未知，分析时补齐
```

那么理所当然：

```text
几何：默认 dummy 便签，在乎时上真模型
```

**形态学就是另一个"懒"维度。Lazy Geometry。**

# 二、正式化：几何保真度是每个对象的独立属性

给每个对象一个可升级的几何等级：

```text
G0  便签块      灰积木 + 传记（默认，万物皆可）
G1  示意原语    圆柱、堆、层叠——有比例、有高矮胖瘦
G2  参数化形态  花边圆柱、分层剖面、编织格——由参数生成
G3  自由建模    真正的 CAD/雕刻/导入 mesh——你的 Rhino 月饼
```

关键规则只有三条：

## 规则 1：任何对象、任何时刻，都可以单独升级

不是"整个项目选一个精度"，而是：

```text
桌上一堆 G0 灰块中间，
立着一个 G3 的精致月饼。
```

这个画面不但不违和，反而**是你产品最强的视觉语言**：精致度本身在说话——"这个对象是被在乎的"。就像侦探板上大部分是便签，但正中间钉着一张真实照片。

## 规则 2：几何升级不改变语义地位

G3 月饼和 G0 灰块在系统里完全平等：

```text
同样的事件链
同样的传记
同样的物料关系
同样可以是"上游未定义"的孤儿
```

漂亮的模型不获得任何语义特权，丑的 dummy 不缺任何功能。**形态是表达，不是承诺**——这句话要写进产品原则。

## 规则 3：升级发生在"你在乎的时刻"，通常是末端，但不限于末端

你说"最末端放 CAD"，大多数时候对——成品是形态学价值最密集的地方。但也有中途在乎的情况：

```text
编织派皮：入炉前的顶面就是作品
拉糖：过程中的造型就是全部
切面设计：这是设计意图，甚至在制作之前
```

所以不硬性规定位置，只提供动作：

```text
右键任何 dummy → "赋予形态"
  ├── 选一个参数化模板（G2）
  ├── 打开建模视图（G3）
  └── 导入外部模型（G3，你的 Rhino 月饼直接拖进来）
```

# 三、你的月饼工作流，在这个体系下的完整样子

```text
1. 拖一个 dummy 到桌面           → G0 灰块
2. 便签写"月饼"                  → 有身份的孤儿对象（红角标：上游未定义）
3. 右键 → 赋予形态 → 打开建模    → 拉花边圆柱、放变形球，或直接导入 .3dm
4. 现在桌上有个精致月饼          → G3，但仍然是孤儿
5. 之后某天，补事件链：
   "皮从这团面来，馅从那锅莲蓉来，
    模具压制，180°C 烤 20 分钟"
6. hover 月饼：
   "由莲蓉馅与浆皮面团经模具压制成型、
    两次刷蛋液烤制的广式月饼"
   ——传记和形态终于会师
```

**这就是你最初的直觉的完整实现**："它可以先是一个月饼"，而且是一个**漂亮的**月饼，语义之后慢慢长上去。

切面同理：G2/G3 几何天然支持剖切视图。定制蛋糕的分层剖面甚至可以是**设计入口**——先画切面（这是意图，G2 参数化分层），再反向生成各层对象的 dummy，每层一张便签，然后分头补各层的工艺。**从形态开始向上游生长，和从原料开始向下游生长，在这个体系里完全对称。**

# 四、工程上这为什么不重

你之前怕的是"3D 资产问题"——给厨师机、烤箱、几百种食材建模。现在：

```text
G0：一套 dummy 原语，一次做完        ← 覆盖 95% 对象
G1：十几个基础形状（圆柱/堆/层/blob） ← 顺手
G2：三五个参数化模板（分层体/花边压模/编织格）← 每个一两天，做几个撑门面的
G3：不自己做建模器！                  ← 关键决策
```

G3 的正确实现是 **导入优先**：

```text
支持拖入 .stl / .obj / .glb（Rhino/Blender 都能导出）
+ 一个极简的原语组合编辑（可选，砍掉也行）
```

你本来就会 Rhino。让"专业形态在专业工具里做，CakeCAD 负责让它获得历史和身份"——这反而是最干净的分工，也符合你们"不重造轮子"的纪律。黑客松版本甚至可以只做 G0 + 导入，G2 模板做一个花边圆柱用来演示月饼，就够了。

# 五、这个设计还白送一个叙事高潮

想象演示的最后一幕：

```text
整场 demo 都是便签和灰块——评委已经接受了这个世界观。
最后你说："当然，当你真的在乎它长什么样的时候——"
右键月饼灰块 → 导入模型
一个精致的花边月饼落在一桌便签中间，
红绳依然连着它的莲蓉馅批次和烤箱事件。
hover 上去，传记浮现。
剖开，切面分层可见，每层可点，各自有便签。
```

**"我们不渲染你不了解的东西；但你在乎的东西，值得一个真正的形状。"**

这一幕同时证明了：便签沙盒不是能力不足的遮羞布，而是一个**有意识的保真度调度系统**——形态学没有被丢掉，它被放到了它该在的位置：稀疏、按需、和在乎成正比。

---

一句话收束：

> **Lazy semantics, lazy simulation, lazy geometry. 三个懒是同一个懒——系统对世界的了解和承诺，永远只在用户在乎的地方变深。**

月饼安全了。而且比在原 CakeCAD 里更安全——因为现在它不需要整个 3D 资产体系陪葬，一个人就能漂亮地存在。
