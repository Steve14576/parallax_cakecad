### 什么样的垂直才配得上你这两块底牌

原则：**垂直的是场景和叙事，不是能力。**

下面这些都故意避开“智能黑板 / 知识操作系统 / 通用节点编辑器”这种一听就撞的包装。

**更适合讲解引擎（DSL + 幻觉防治）的切片**
- **可打断的“活推导”**：只打一个公认难讲的东西（某个数学直觉、控制里的反馈、Transformer 里的一个机制）。用户随时打断、改假设，动画和逻辑一起重编译。卖点不是生成视频，是**讲着讲着还能保持自洽**。
- **死黑板复活**：拍一张真实板书 / 教材页 / 手写推导，变成可交互讲解。这比纯生成更难被说成“套了个 LLM”。
- **故意笨的学生 + 活板书**：你教 AI，AI 根据你的讲解在画布上长结构；你讲错了，图会以一种很精确的方式垮掉。教育赛道很好讲故事。

**更适合节点引擎（UX + 插件兼容）的切片**
- **一张会跑的因果/反馈图**，只服务一个高痛思考场景：比如“我以为想清楚了，一跑才发现没想清楚”。不要说能挂万物，只说这个场景里节点少、反馈真、改完立刻看见涟漪。
- **个人思维外骨骼（极窄版）**：不是第二大脑，是“把你正在纠结的那个系统画出来并能跑”。生活赛道或知识赛道都能走，但必须限定问题类型。
- **把传统“死图”变成可执行物**：表面上是学习工具，底下是你的运行时。评委看到的是体验，不是生态野心。

**差异化最大、也最不像工具的**
- 游戏：规则就是那张可跑的图，讲解是实时长出来的。通关方式是改结构，不是打怪。这能同时用上两套能力，还不容易被归类成“又一个编辑器”。
- 人文：把一段关系、一个执念、一次选择编成可交互系统。人不是在用工具，是在看见结构。这类评委记忆点很强，但叙事要克制，别做成鸡汤。

不管选哪个，**只做一个英雄演示回路**：

输入/打断 → 结构变化 → 动画或数值立刻跟着变 → 人产生“原来如此 / 原来我错了”的瞬间。

没有这个瞬间，扩展性等于零分。

### 怎么避免“正经做时从底层重写”

重写通常不是因为垂直，而是因为这四件事漏进了核心：

1. **领域对象进内核**  
   `Lesson` / `Student` / `KnowledgeCard` 这种东西一旦进 runtime，后面平台就要剥皮。内核只该有 `Expr` / `Graph` / `Node` / `Patch` / `Trace` / `Constraint` 这类词。
2. **为完整而实现假能力**  
   挂 Simulink、Grasshopper、LangGraph、黑板——黑客松里做这些，几乎一定是假的。假兼容会把插件模型做歪，这比没做更贵。
3. **提示词当编译器**  
   讲解引擎如果靠“再写长一点的 prompt”撑过演示，你后面几乎必然重写。编译器和幻觉防治必须在这 48 小时里以缩小的语言出现，哪怕只能表达 8 个概念。
4. **成功后的义务感**  
   “都做出来了，不用可惜。”这是身份问题，不是技术问题。提前规定：演示不是公司。

反过来说：如果你这 48 小时只做 **真实子集上的真实回路**，后面不是从零重写，而是换掉演示用的实现，留下语义。编译器作者和节点引擎作者都是这么过来的——扔代码，留语言。

一个硬规则：

> 每一个打算写的功能，都问：  
> **下个月做正儿八经的 DSL / 节点内核时，我会不会以同一种语义再做一遍？**  
> 会 → 可以做真的。  
> 不会 → 不要做真的，用预录、预计算、半人工、单场景硬编码把演示扛过去。

黑客松里，**宁可用假皮肤保护真内核，不要用真功能污染真内核。**

3. **身份被钉死**

所以：  
**有意避开，保护的是“尚未硬化的内核 + 你还想当平台作者这件事”，不是保护一个没人想过的 idea。**  
如果回避的理由是“我怕别人听到概念就做出来”，这个怕法对 meta 想法通常过重。如果回避的理由是“我不想在火候不够时，把回路、约束和品味摊在台上”，这个怕法是对的。

“要么一次成功，要么火候不够于是 idea 泄露被抢”——这个二分法不成立。  
真正的差的结果是第三种：**演示既不够硬，又把那句最值钱的话讲出去了。**  
成功也不等于底牌被兑现；失败加讲清楚，才接近你说的泄露。

别人抢得走的是品类和皮；抢不走的是编译器、约束、UX 手感、以及你愿意为可扩展性多活两年。能在 48 小时里复制你底牌的人，本来也不靠看你路演才开工。

### 怎么避才真的避干净

“换个垂直外壳，内核还是那两套”不算避开。评委不在乎你自称不是平台，他们只记得那个瞬间。那个瞬间一旦成立，品类就亮了。

真避开的标准是：

- 演示里**不出现**可打断的活讲解、活黑板、可跑的知识图、节点连线当运行时
- 代码里**不出现**你正经仓库里那套 `Expr / Graph / Patch / Constraint` 语义
- 路演里**不出现**“以后能挂 Simulink / 这是一种新语言”这种话
- 赢了之后，你也**不会**觉得该把这个作品接进那两个产品

满足这四条，才叫保护。否则只是换皮，泄露路径还在。

2. **你本来就不打算做的垂直玩具**  
   生活里一个很痛的小工具、一个很人文的小实验。它甚至可以很完整。完整也不伤，因为你没有打算让它成为公司。
3. **信息探针，但探针的不是那两套内核**

### 物理仿真：三层拆解，回答你“黑箱 NN 还是拿数据”的问题

**先说结论：不要做黑箱神经网络。** 原因很直接：
1. 10 天里你拿不到真实、有标签的糕点力学数据，训练黑箱等于训练噪声。
2. 黑箱和你项目真正的价值主张（讲清楚“为什么”）是矛盾的——你恰好有 LLM 这种最适合“解释因果”的工具，为什么要换成一个连你自己都解释不了的黑箱。
3. 时间成本上，黑箱比下面的方案更贵、更假、更难演示。

把你提到的现象分成三层，分层处理，不要用同一种精度打所有问题：

**第一层：真的有公开、可计算、不需要专有数据的物理——就做真的**

- **牛排/蛋羹/慕斯的“熟没熟”本质是热传导 PDE**，不是玄学：
  $$\frac{\partial T}{\partial t} = \alpha \frac{\partial^2 T}{\partial x^2}$$
  肉类热扩散系数 α ≈ 1.3–1.5×10⁻⁷ m²/s，这是公开发表的常数（低温慢煮计算器 Baldwin's Sous Vide 用的就是这套方法），不需要任何机密数据。用显式有限差分几行代码就能实时算出芯温随时间变化，对照“三分熟 ~52℃ / 五分熟 ~58℃ / 全熟 ~68℃”这类公开阈值，**这是一个可以在评委面前站得住的真实剖面动画**，不是演。

- **藏红花 gelato 的 overrun 也有公开公式**，不是黑箱：
  $$\text{Overrun\%} = \frac{V_{\text{成品}} - V_{\text{原料}}}{V_{\text{原料}}} \times 100$$
  你甚至可以用一个厨房秤自己做一次真实测量当基准，剩下用打发时间/速度拟合一条看起来合理的气泡混入曲线。这比“藏红花很贵所以要测试”更进一步——你可以直接告诉评委“这个数字是行业标准指标，我们真的算了”。

**第二层：没有干净公式的现象——用透明的启发式打分，而不是伪装成仿真**

海绵蛋糕会不会塌，没有一个像热传导那样干净的闭式解。**不要硬凹 FEM，也不要黑箱**，用可解释的比例规则：液体:面粉:脂肪:发粉的配比、烘烤温度/时间相对于“定型曲线”的位置，算出一个风险分数，**分数是确定性代码算的，不是 LLM 编的**。

**第三层：纯视觉的“塌”——Unity/Three.js 级别的假动画，明确当假**

第二层算出的风险分数一旦过阈值，触发一个 shape key/morph target 让蛋糕在屏幕上真的塌下去。这一步是纯粹的戏剧效果，不需要伪装成物理仿真，观众也分不出来，而且这才是真正让人“哦”一声的瞬间。

**这三层合起来就是你的答案**：真实物理只拿一个最值得拿的现象（推荐热传导，因为它最干净、最可信、最不需要数据），其余用透明启发式 + 视觉戏剧效果顶上，全程不用黑箱。

### LLM 该干什么活：叙述层，不是推理层

这里有第二个隐蔽的撞车风险。如果你让 LLM **自由推理**“这个蛋糕为什么会塌”，你就是在临时发明一个没有约束的因果推理引擎——这正好是你另一张底牌（DSL + 幻觉防治）想解决的问题的一个简化版。

**解法**：第二层的风险分数由确定性代码算出来，LLM 只负责**把这个数字翻译成一段有温度的解释和故事**，并且顺手把溯源信息编进去。比如：

> “液粉比偏高了 18%，谷蛋白网络撑不住内部水分——这就是为什么它会在冷却时塌陷，就像你外婆那次用错了面粉一样。这颗草莓来自云南，三天前刚采下来。”

数字是算的，故事是讲的。LLM 干它最强的那件事（自然语言、温度、类比），不碰它这次不该碰的那件事（因果推理本身）。这样你既用好了 AI，又没有在暗地里重新做一次你的编译器平台。

## 关于你问的"撞离散"

你的直觉是对的，而且这个问题有名字。蛋白质变性、乳化、米饭返生（淀粉回生/retrogradation）——这些是**相变类现象**，它们的共同特征是：

**输出不是连续函数，而是状态跳变 + 路径依赖 + 不可逆。**

具体撞在哪：

**1. 不可逆性 → 你不能用状态量插值**
蛋白变性了就回不去。米饭返生后即使加热也不完全恢复。这意味着"当前状态"不能只由当前温度决定，必须由**历史积分**决定。传热学里你可以说"芯温58℃"就够了，这里不行。

**2. 阈值不是点，是路径**
"蛋白什么时候凝固"没有单一温度答案。62℃保持30分钟 ≠ 80℃保持10秒，即使某种意义上"熟度"相同。这就是为什么低温慢煮有巴氏杀菌**表**而不是巴氏杀菌**公式**——工业界自己也是查表的。

**3. 多个亚稳态 → 同参数不同结局**
乳化最典型：同样的配比、同样的温度，加油速度差一点就是"成功的蛋黄酱"vs"油水分离"。这不是你数据不够，这是系统真的有分岔。

**你的架构其实已经能容纳这些，只要在条目schema里加两个字段：**

- `path_dependent: bool` — 若为真，该条目的输入不是标量而是时间序列（或其积分）
- `outcome_type: continuous | categorical | bifurcating` — 分别对应"给数值""给类别+置信度""给多个可能结局+各自概率"

对于相变类现象，工业界的标准做法就是**你已经想到的那个**：累积效应积分。比如热处理领域的 $F$ 值、$P$ 值，或者时间-温度积分：

$$
\Phi = \int_0^t k(T(\tau))\, d\tau
$$

其中 $k(T)$ 通常取 Arrhenius 形式 $k = A e^{-E_a/RT}$。这个积分值过阈值就跳变。**这个框架能吃掉蛋白变性和淀粉糊化的绝大部分工程需求**，而且文献里有大量 $E_a$ 数据可以入库——完全符合你"论文百分之百入库"的目标。

乳化那种真分岔的，老实说，就不给数值，给**类别+置信度+"这个点离已知失败区多远"**。这反而是诚实的输出。

## 你的"懒仿真"需要的是一个 Evidence Ladder

我建议把置信度做成**显式的证据等级**，而不是一个浮点数。因为浮点置信度会让人误以为它是概率，而你的不确定性主要来自"我凭什么外推"，不是统计噪声。

| 等级 | 含义 | UI 表现 | 例子 |
|---|---|---|---|
| **L0 解析** | 有闭式解/成熟PDE，公开常数 | 实线，给数值 | 1D热传导芯温 |
| **L1 半经验** | 无量纲数+文献经验关联式 | 实线+误差带 | 打发时间→overrun曲线 |
| **L2 内插** | 有多点实测，在包络内 | 虚线+置信区间 | 3个糖浆温度实测，问中间值 |
| **L3 邻域外推** | 单点实测+机理方向已知 | 点划线+"仅供方向参考" | 明天糖浆烫5℃会怎样 |
| **L4 类比** | 无本体数据，借相邻体系 | 灰色+明确标注"类比自XX" | 没测过藏红花，借香草gelato |
| **L5 未知** | 拒绝回答 | 空白+"缺少数据" | — |

**关键设计：等级不可被组合运算提升。** 如果一个结果依赖L3输入，它最多是L3。这是防止"垃圾进垃圾出但看起来很精确"的唯一办法。这条规则你必须在求解器里硬约束。

用你的例子：明天糖浆烫一点，多搅一会救不救得回来。
- 糖浆温度→黏度：可能L1（有文献关联式）
- 黏度→蛋白泡沫稳定性：可能L3（你只有一个点）
- 搅拌时间→补偿量：可能L4（借类比）
- **最终输出：L4，给方向 + "建议实测验证"**

这个输出比一个假装精确的数字有用得多，而且**诚实本身就是演示卖点**。

5. **不要给它起一个通用名字。** 不叫 engine、runtime、kernel、framework。叫 `recipes/` 和 `phenomena/` 就好。

## 关于"论文入库"这个卖点

这是你整个项目里我最喜欢的部分，而且它可能才是真正的差异化。

"任何论文我们都能100%入库，机理深不深另说，泛化强不强另说，但你就说数据用没用上吧"——这句话如果做成一个可演示的动作，杀伤力很大：

**现场从一篇论文（或一张表格）里录入一条新数据 → 系统立刻多出一个L2/L3能力 → 重跑刚才那个查询 → 置信度从L4升到L2。**

这个瞬间比任何仿真动画都有说服力，因为它展示的是**系统会成长**，而且成长路径是诚实的（数据→能力→置信度）。

10天里做到这个不难：录入表单+一个YAML文件+重新查询。但演示效果远超实现成本。

## 修正后的项目定位

不是"蛋糕CAD"，也不是"厨房CAE"。是：

> **一个诚实的食品现象求解器：它明确知道自己知道什么、不知道什么、以及凭什么这么说。**

这个定位：
- 避开了"厨房仿真不可能"的合理质疑（你从没声称能算）
- 把"数据不足"从缺陷变成了核心设计（Evidence Ladder）
- 让"论文入库"成为可演示的成长机制
- 和你两张底牌的语义重叠可控（只要守住上面那5条纪律）

赛道上，这个版本更偏**知识奇点**了——它本质上是在教人"如何在证据不足时诚实地推理"，这比"教你做蛋糕"高一个层级。

## 10天范围建议（修正版）

| 模块 | 处理 |
|---|---|
| L0 传热（芯温） | 做真的，1D显式差分，公开α |
| L1 一条半经验曲线（overrun或打发） | 做真的，文献关联式 |
| L2/L3 一到两个数据条目 | 手工录入2-4个真实数据点，做邻域外推 |
| Evidence Ladder + min()传播 | **核心，必做**，这是项目灵魂 |
| 相变类（选一个：蛋白或淀粉） | 用Arrhenius积分，输出categorical+置信度 |
| 论文/数据现场入库 → 置信度提升 | **必做，这是hero moment** |
| 3D可视化 | 够用就行，塌陷动画可以是shape key |
| 时间轴 scrubber | 硬编码序列，不做DAG |
| 通用插件注册/拓扑求解 | **Kill，这是底牌** |
| 黑箱NN | Kill（数据量不支持） |
| 多维耦合 | Kill，只在有实测的单点上标注"此处已耦合" |

## 我还需要你确认两件事

1. **相变类你想选哪一个做示范？** 蛋白变性（数据最多、最直观、和打发/蛋糕直接相关）、淀粉糊化/回生（和米饭、蛋糕老化相关）、还是乳化（最戏剧化但最难给数值）。选一个做深，别三个都碰。

2. **"论文入库"的入口形态？** 是手填表单（最稳）、还是贴一段文本让脚本解析（中等）、还是真的丢PDF进去（最炫但10天内容易翻车）。这直接决定你的hero demo长什么样。

另外——你提到"软件本体要不要LLM两说，做个CLI斜杠呼唤agent"。这个设计我赞成，而且它正好和Evidence Ladder配套：**agent只能调用已注册的条目，不能自己编数值**。这样LLM的角色就是"帮你找到该查哪条、并把L3警告翻译成人话"，而不是推理引擎。这个约束写进system prompt就行，10天够。
