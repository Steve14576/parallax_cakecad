# 曲奇首个纵切 Feature Spec

> 文档状态：正式下游规格初稿  
> 上游约束：`docs/MASTER_SPEC.md`  
> 适用范围：首个可交互验证版本，不代表最终 UI、文件格式或技术实现  
> 变更纪律：本文件只能收窄和展开 `MASTER_SPEC`；发现冲突时先修改上游

## 1. 目标

本纵切用一条曲奇制作流程验证 CakeCAD 最核心的闭环：

> 用户可以先随便写、随便摆，再把其中一部分提升为可追踪的时间化事实；系统按需分析，并允许从任意时刻创建不污染主线的变体。

完成后，演示者应能在一个项目中证明：

- Markdown 可以自由记录，但不会偷偷变成脚本或事实；
- 对象、位置、操作和状态可以沿时间查看与编辑；
- 空间摆放与物料流转不是一回事；
- 用户可以命名中间体并决定何时形成新对象；
- 分件产生子对象，烘烤保持曲奇对象连续性；
- 不完整时间、未知质量和暂时不守恒不会阻止创作；
- 分析只读取局部所需事实，不冒充全局物理真相；
- 实测数据可以回填，且不会被预测覆盖；
- 分支共享上游、局部变化、可比较且不污染主线。

## 2. 本纵切明确不解决什么

本纵切不承担以下任务：

- 完整厨房 3D、真实食物材质、碰撞和流体仿真；
- Rhino、Blender 等级的建模器；
- 参数化食物资产库或外部 CAD 导入；
- 通用节点编辑器；
- 完整命令语言或插件系统；
- 科学上完备的烘烤模型；
- 自动理解整篇 Markdown 并生成完整流程；
- 多文件过程单元、外部配方引用与循环依赖处理；
- 分支合并；
- 协作、云同步、发布、迁移和备份；
- 所有五种分析方式的完整实现；
- 最终 UI 布局与最终视觉规范。

这些能力仍受 `MASTER_SPEC` 约束，但不作为本纵切验收条件。

## 3. 本纵切采用的验证载体

为控制范围，本纵切采用二维语义代理画布，不制作完整 3D 工作区。

画布只需支持：

- 放置便签式对象代理；
- 拖动对象以改变画布位置；
- 把对象放入容器代理；
- 选择一个或多个对象；
- 通过标题、辅助色条和状态标记识别对象；
- 从对象跳转到时间轨、来源和传记。

二维画布是首个验证版本的实现选择，不构成 CakeCAD 长期放弃 2.5D、3D 或基础建模的决定。

## 4. 最小工作面

本纵切必须提供以下能力，但不固定它们位于屏幕的左、右、上、下。

### 4.1 Markdown 底稿

必须支持：

- 自由编辑 Markdown；
- 保存不完整、错误或互相冲突的文字；
- 插入指向对象、事件、时间片段、分支和分析结果的定位书签；
- 点击书签跳转到对应事实。

不得支持：

- 把 Markdown 当作 CakeCAD 脚本执行；
- 因出现“加入”“烘烤”等词语自动提交事实；
- 让事实变化静默重写用户原文。

### 4.2 DAW 时间轨

本纵切中的 DAW 是时间化事实的主要查看与编辑入口。

至少支持：

- 在“物料＆操作”和“物料＆位置”两种投影之间切换；
- 显示对象存在区间、持续操作、事件和有效关系；
- 拖动整个片段；
- 拖动片段首尾边界以改变开始、结束和持续时间；
- 新操作默认形成一个短的可编辑片段，而不是永久坍缩为瞬时点；
- 表达精确、近似、未知和开放结束时间；
- 从轨道空白处或上下文菜单新建对象；
- 选择多个对象后执行同一命令；
- 从某个时间点创建分支。

本纵切的 DAW 必须显示当前时刻指针（playhead）：新片段默认落在指针处，拖动或点击轨道可移动指针。playhead 是用户的注意力锚点，不是强制时间约束。

轨道编辑写入共享事实底座，不维护独立副本。

### 4.3 热区与冷区

热区与冷区描述 DAW 中线段和过程的呈现状态，不是工作区图层开关。

- 热区汇集被搬出来操作、正在参与变化、正在编辑或选中的片段，并允许这些线段发生汇聚、转化、产生新对象或形成分支。
- 冷区显示当前没有参与主要操作、但在所选时段仍存在的对象、位置和关系，用于回答“这个时段还有什么”。
- 操作结束或对象不再需要主动编辑时，它可以从热区撤下，但仍在冷区、历史和检索中存在。
- 热区/冷区切换只改变 DAW 中的呈现，不改变对象身份、空间位置、历史或工作区可见性。
- 用户可以在冷区查找对象，并将它带到热区参与某个新操作；这不是把对象从“库存”里复制一份。

### 4.4 语义代理工作区

工作区至少支持：

- 自由摆放代理物；
- 记录画布位置；
- 多选对象；
- 通过右键、工具栏或 CMD 声明 `located_in`、物料转移或其他关系；
- 将空间动作保留为草图，或由用户显式确认其物料/过程意义；
- 显示对象标题、类别辅助标记和对象传记。

仅仅把原料代理拖到碗上，不得自动断言原料已被倒入、消耗或混合，也不得把“靠近就弹窗”作为默认提交流程。拖拽可以产生草图记录；是否成为正式事实，应由右键、工具栏、CMD 或明确的后续确认决定。

### 4.5 CMD

CMD 用于验证 CAD 式键盘操作是否适合 CakeCAD，不追求完整语言。

本纵切至少覆盖以下语义动作：

- 新建对象；
- 放入容器；
- 命名或改名；
- 开始与结束持续操作；
- 分件；
- 记录测量；
- 创建分支。

对适用动作必须同时验证：

- 先选择对象，再输入命令；
- 先输入命令，再选择一个或多个对象；
- 右键菜单中先选对象再执行动作；
- 工具激活后连续点选一个或多个参与对象，Enter 确认。

右键菜单包含通用动作和由对象角色决定的专门动作；工具栏与 CMD 提供相对稳定的通用动作。具体英文/中文命令名、参数语法、菜单分组和自动补全形式不在本文件中锁死。

### 4.6 节点图

本纵切不实现可编辑节点图。

原因是节点图与 DAW 是同一事实的不同投影，而本纵切首先验证时间化操作是否成立。底层事实必须保持可被未来节点图投影，但不得为尚未实现的节点 UI 预设 Port、Flow 或固定节点类型体系。

## 5. 初始对象

演示项目至少包含：

### 5.1 物料

- 面粉；
- 糖；
- 黄油；
- 蛋；
- 巧克力豆。

### 5.2 容器、工具与设备

- 搅拌碗；
- 厨师机；
- 烤盘；
- 烤箱。

对象初始数量可以部分已知、部分未知。每个对象必须有稳定 ID、可读标题、角色辅助标记和存在状态。

## 6. 标准演示流程

### 6.1 自由底稿

1. 用户写下一段不完整 Markdown，例如配方意图、担忧和模糊条件。
2. 文字可以包含“黄油可能要软化”“烤到边缘上色”等尚未提交的内容。
3. 此时事实底座不因文字内容而自动新增操作。

### 6.2 摆放与物料提交

1. 用户在工作区摆出碗、原料、厨师机、烤盘和烤箱。
2. 用户把原料代理拖到碗附近或碗内。
3. 系统先记录空间草图。
4. 用户确认部分动作是物料转移。
5. 系统建立有时间范围的包含/位置关系，并记录相应加入事件。

验收重点：空间位置与物料事实必须可分开查看。

### 6.3 持续混合与中途加料

1. 用户建立一个持续的“混合”操作区间。
2. 用户在区间中途加入黄油、蛋和巧克力豆。
3. DAW 必须能表现这些点事件位于持续操作内部。
4. 操作结束时间可以先未知，之后再补。

### 6.4 用户确认“曲奇面团”

1. 原料共处于碗中时，系统不自动创建面团对象。
2. 用户明确命名当前混合结果为“曲奇面团”。
3. 系统创建可独立引用的结果对象。
4. 面团通过来源关系指向参与形成它的原料。
5. 输入对象保留历史，并记录其数量被使用、分配或暂时未知。

### 6.5 分团

1. 用户把曲奇面团分成若干份。
2. 每份获得独立子对象 ID。
3. 子对象通过来源关系指向曲奇面团。
4. 曲奇面团整体在分件后保留历史，但当前可用数量相应减少或处于未完全分配状态。
5. 子对象质量允许未知或近似。

### 6.6 摆盘与入炉

1. 用户把曲奇团自由摆放在烤盘上。
2. 工作区和“物料＆位置”轨显示曲奇团与烤盘的关系。
3. 用户将烤盘放入烤箱。
4. 该动作默认建立容器/位置关系；烘烤操作必须由用户另行开始，不能仅凭空间包含自动推断。

### 6.7 烘烤与对象连续性

1. 用户创建持续的烘烤操作。
2. 结束条件可以写成“到边缘上色、中心偏软”，而不是强迫输入精确分钟数。
3. 生曲奇到熟曲奇默认保留同一对象 ID。
4. 烘烤前后通过状态时间片段区分，不创建一套凭空入场的熟曲奇对象。
5. 用户仍可明确要求某次过程产生新对象；该覆盖必须留有记录。

### 6.8 先验建议与过程指导

本纵切只实现两个轻量分析入口：

- 先验建议：根据当前已知输入给出建议观察范围，并列出缺失输入和依据；
- 过程指导：把建议表达为时间轨上的观察窗口或提醒。

分析结果必须：

- 明确标记为派生结果；
- 展示使用的输入、模型标识和适用范围；
- 在输入变化后标记过期；
- 不自动修改烘烤时间、对象状态或用户原文；
- 在信息不足时诚实返回“无法收窄”，而不是编造精确结论。

本纵切验收分析生命周期与可追溯性，不验收烘烤模型的科研准确性。具体模型应使用可替换且明确标记的演示模型。

### 6.9 实测回填与后验检查

1. 用户记录实际烘烤时间、出炉总质量和一条观察，例如“边缘上色、中心偏软”。
2. 实测值成为测量事实和锁点。
3. 系统运行后验检查，对比先验观察窗口与实际记录。
4. 后验结果可以指出偏差和未知项，但不得覆盖实测。

### 6.10 分支与比较

1. 用户从混合前或混合开始处创建“黄油软化版”分支。
2. 分支继承此前对象、事件和关系。
3. 用户仅修改黄油状态或相关处理。
4. 主线保持不变。
5. 比较视图至少显示：共同祖先、分叉点、被修改事实、失效分析和两边结果。
6. 本纵切不要求把分支合回主线。

### 6.11 Markdown 书签闭环

用户至少创建以下书签：

- 指向持续混合区间；
- 指向“曲奇面团”对象；
- 指向烘烤观察窗口；
- 指向后验检查结果；
- 指向“黄油软化版”分支。

点击书签应跳转到对应工作面和时间位置。事实变化后书签仍指向同一稳定对象；若目标失效或被删除，书签必须明确显示断裂，而不是跳到错误对象。

## 7. 最小事实覆盖

本纵切必须实际生成并可查看：

- Object：原料、容器、设备、面团、曲奇子对象；
- Event：加入、混合开始/结束、命名、分件、入炉、烘烤、观察、创建分支；
- Relation：位置/包含、来源、工具或设备作用；
- Time Segment：对象存在、持续操作、状态和关系有效期；
- Measurement：实际烘烤时间和出炉质量；
- Branch：主线与黄油软化版；
- Analysis Case / Result：先验建议、过程指导、后验检查；
- Conflict：未知质量、未分配量、过期分析或断裂书签中的至少一种；
- Lock：由实测产生的不可静默覆盖边界。

## 8. 对象传记与视觉表达

代理物以文字标题为主要身份标识，颜色和横杠只做辅助区分。用户修改颜色只改变显示样式。

至少为以下对象生成可追溯传记：

- 曲奇面团；
- 任意一个曲奇子对象；
- 烘烤后的同一曲奇对象。

传记必须从已确认事件、关系、用户命名和测量中生成。每条重要陈述都应能跳回来源。用户不能直接覆盖传记正文，但可以新增 Note 或修改底层事实。

分析状态使用独立徽标、边框、结果卡或时间轨覆盖，不得与用户自定义颜色混淆。本纵切不要求网格或写实预览。

## 9. 验收标准

纵切只有同时满足以下条件才算完成：

1. Markdown 中的流程文字不会自动产生事实。
2. 用户可以从 Markdown 书签跳到 DAW 中的混合区间。
3. 拖动物料进入碗时，系统不会自动弹出强制确认框；用户可通过右键、工具栏或 CMD 选择仅记录空间摆放或确认物料转移。
4. DAW 能显示持续混合以及其中途的加料事件。
5. 用户命名前，系统不擅自创建“曲奇面团”。
6. 用户命名后，面团成为具有来源关系的独立对象。
7. 分团产生多个子对象，且能追溯到同一面团。
8. 烘烤前后曲奇保持同一对象 ID，并显示状态变化。
9. 烘烤结束条件允许模糊描述或开放结束。
10. 先验分析明确显示输入、缺失项、依据和有效范围。
11. 输入变化后旧分析结果显示过期。
12. 实测时间和质量不会被分析覆盖。
13. 后验检查能引用实测并显示与先验结果的差异。
14. 主线创建分支后保持不变。
15. 分支比较能显示分叉点和局部修改。
16. 热区与冷区切换只改变 DAW 中线段呈现，不改变对象事实或工作区可见性。
17. 至少一个核心动作可通过先选对象后输入命令完成。
18. 至少一个多对象动作可通过先输入命令后多选对象完成。
19. 对象传记中的关键陈述可以回查来源。
20. 整个流程不依赖可编辑节点图、完整 3D 或真实物理仿真。

## 10. 失败条件

出现以下任一情况，说明纵切偏离 CakeCAD：

- Markdown 被当作流程脚本执行；
- DAW、工作区和 CMD 各自保存一份事实并互相同步；
- 拖入容器就自动等同于消耗、混合或开始烘烤；
- 靠近容器就强制弹窗打断操作；
- 所有时间都被强迫填写为精确数字；
- 未知质量阻止用户继续；
- 熟曲奇以无来源的新对象凭空出现；
- 分析结果覆盖测量或冒充事实；
- 用户必须先搭节点图才能制作曲奇；
- 为了完成演示而建设完整 3D 资产库；
- 分支修改回写并污染主线。

## 11. 本规格保留的开放项

以下问题不由本文件拍板：

- 工作面最终布局；
- 2D、2.5D 与 3D 的长期组合；
- 完整 CMD 词汇、语法和快捷键；
- 右键菜单的具体分组、自定义动作生成规则和菜单编辑器；
- 节点图何时进入产品；
- 科学烘烤模型及其证据等级；
- 对象传记使用规则生成还是 Agent 生成；
- 项目文件和事件存储格式；
- 分支底层实现与未来合并规则；
- 用户覆盖对象身份默认判据的最终交互；
- 完整的实测执行记录模式。

这些问题只能通过后续 UX Spec、ADR、TRD 或上游 `MASTER_SPEC` 修订解决。

## 12. 完成后的下一步

本纵切规格通过确认后，后续文档顺序应是：

1. 针对本纵切制作低保真交互原型；
2. 根据原型确认工作面切换和最小 CMD 动作；
3. 编写领域事实底座 ADR；
4. 编写本地项目存储 ADR；
5. 生成实现 Plan；
6. 分阶段实现并逐条跑通本文件的验收标准。
