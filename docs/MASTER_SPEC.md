# A. 产品定义

## A.1 一句话

CakeCAD 是一个本机优先的过程研发工作台：以时间为坐标系，记录物料、工具、设备与中间体如何出现、移动、组合、分离与演化。

> 菜谱软件记录你打算做什么；CakeCAD 记录你的厨房里实际发生了什么。做出来之前不必定义，算得动的时候才要求严格。

哲学一句话：**自由地摆，诚实地记，按需绑定，局部地算。** 自由在表达端，诚实在记账端——创作时开门，记账时关门。

## A.2 它不是什么

| 不是 | 因为 |
|---|---|
| 菜谱游戏 | 对象不预设命运 |
| Creo/SW 式强约束特征树 | 允许先画先写先命名，历史可悬空 |
| Blender 食品版 | 核心是记录物质过程，不是捏模型 |
| ANSYS/COMSOL 食品版 | 仿真只在提问时局部启动 |
| SaaS 协作平台 | 本地文件、本地计算，第一年单机单人 |
| 菜谱社区 | 不做内容分发 |
| 通用节点平台 | 内部可有 DAG，不暴露为任意工作流编辑器 |

## A.3 用户与场景

主要用户：作者本人；本人 + AI 工具协作开发。首个验收场景：黑客松演示——曲奇纵切（B.9）。以食品为切入点，抽象适用于实验室/工坊/小批量制造。

## A.4 根原则

1. **开放世界**：未知 ≠ 不存在，未定义 ≠ 错误，不可分析 ≠ 不可编辑。
2. **局部闭合**：只让当前任务相关的部分严格。
3. **软类型**：对象先只有名字，角色随任务渐进附加。
4. **事实、解释、假设、预测分离**：预测不覆盖实测，解释不冒充事实。
5. **容错式创作**：悬空、缺失、不守恒是合法状态；系统负责知道哪里不闭合。
6. **操作自由，仿真诚实**：表达层敢想敢画；记账层发生过的不改写。
7. **事件为唯一真相，视图皆廉价投影**：前端布局问题不得反向修改数据结构。
8. **未知分层**：unknown 不是一个东西，分七种（C.8）。

## A.5 产品宪法（禁令）

```text
永不精确几何            直到 CAM 真实到来，由 CAM 反向定义精度
永不运行时物理          FFD 烘焙变形封顶
第一年永不云协作        本地文件，本地计算
永不让视图改数据结构    布局问题不是数据问题
永不做全局设计树        只做局部来源图
永不静默修改历史        实测与已执行不可被模型覆盖
永不把猜测当事实        Agent 输出必须过闸门
永不阻止编辑            只报告，不拦路（唯一硬错误：引用不存在的对象）
永不为扩展性牺牲当前完整性
```

## B.2 工作面职责

| 工作面 | 回答什么 | 可写性 | 默认状态 |
|---|---|---|---|
| Markdown 底稿 | 我在想什么、为什么 | 可写（但不自动执行） | 常驻左栏，可折叠 |
| 时间脊柱 | 顺序、持续、当前在哪 | 半可写（点选、拖播放头） | 常驻窄栏 |
| 现场 | 此刻东西在哪、什么形状 | 可写（拖放、谓语） | 中央主体 |
| Header | 此刻正在发生什么 | 只读（纯函数投影） | 常驻一条带 |
| Inspector | 选中对象的档案 | 可写属性 | 常驻右栏 |
| 召唤区 | 并发/来源/分支/账本 | 只读 | 高度 0，按需 |
| 底部抽屉 | 对象库/变量/方法/分析/版本/CMD/导出/搜索 | 可写 | 折叠 |
| 状态栏 | 系统与命令状态 | 只读 | 常驻 |

**CMD 的位置**：CMD 是底部抽屉的常驻标签页，同时支持全局快捷键召唤为浮层（Rhino/VS Code 式）。历史回显保留在抽屉页内；浮层只承担输入与最近一条回显。

## B.3 时间体系：时间脊柱 + Header + 召唤泳道

**全局多轨 DAW 已废止**（L026）。它曾UI设计反向绑架数据结构（容器归属、线段归属、X 形交叉全是伪问题）。

- **时间脊柱**：纵向，贴 Markdown。默认文档式（语义时间，长短事件视觉高度相近，"冷藏 2 小时"不撑爆页面）；双击局部展开为比例式（物理时间）。阶段可折叠。
- **符号**：● 瞬时事件 · █ 持续过程 · ◆ 过程内嵌套事件 · ┊ 未知时长间隔（不吸附）· ▲ 测量点 · ✎ 注释 · ⚠ 未解决冲突 · 灰点（沉默审计，极小）。
- **Playhead**：必须有，可拖动，吸附事件边界，新事件默认落在 playhead。支持物理时刻与逻辑顺序两种位置。
- **MD ↔ 事件锚点**：0..n 关系。一段笔记可挂多事件，一事件可挂多笔记段，无锚点合法。滚动三模式：自由滚动 / 跟随锚点 / 锁定联动。
- **Header**：`f(事件, t) → 状态摘要`，纯函数，零布局算法。内容：正在进行 / 存在的东西 / 最近发生 / 悬空警告（含灰点数）。
- **召唤泳道（T 键）**：选中 2~5 个对象临时展开水平泳道看重叠，只读，Esc 消失。这就是"设计树/甘特图"的合法形态——局部的、召唤的。
- **冷热区概念解散**：Header 即"热"（当前活动），对象库/注册表即"冷"（此刻有什么）。不再有冷热轨道区。

编辑发生在现场、Inspector、CMD；时间脊柱不承担片段编辑（M1 的 clip 拖动能力迁移到召唤泳道与局部比例视图）。

## B.4 命令系统

### B.4.0 注册表是唯一事实源

命令是一份**注册表**，不是散落在菜单、工具栏、CMD 里的三份代码。CLI 是点击命令的平替——同一个定义，三个入口渲染：

```text
命令注册表（唯一事实源）
├── 工具栏  = 按分组渲染成图标按钮
├── 右键菜单 = 按角色过滤渲染成菜单项
└── CMD     = 按名称/别名渲染成可输入谓语
```

谓语与宾语分离：谓语独立注册并声明宾语签名，宾语执行时由点选/多选/参数获得。菜单里不出现“倒入搅拌碗”这种绑死组合项。

### B.4.1 命令定义格式（Rhino 式）

每个命令的正式定义包含：

```text
id/别名       机器名与 CLI 别名
签名          宾语槽位序列：角色过滤器、数量（1 / 1..n / 0..1）、每步提示语
选项          内联参数与默认值
提交级别      sketch / declared / committed
写入          产生哪些事件、关系、对象
撤销          如何回退
```

### B.4.2 选择状态机

```text
idle → selected → armed → picking → preview → commit
Esc 逐级退出：preview → picking → armed → idle
```

先选后动词与先动词后选都合法，落同一状态机。

### B.4.3 命令清单

**新建对象 `new`** — 签名：（名称，角色 0..1）。提交 declared。写入 create 事件 + 新 Object（落在 playhead）。撤销：删除对象与事件。

**命名 `name`** — 签名：object(1) × 名称。提交 declared。写入 name 事件；混合出口自动名可后改。撤销：恢复旧名。

**放入 `place`** — 签名：object(1..n) → container|region(1)。提示：①选择要放入的对象 ②选择目标容器/区域。提交 declared。写入 place 事件 + located_in。撤销：移除关系与事件。

**倒入 `pour`** — 签名：material(1..n) → container(1)。提示：①选择要倒入的物料（可多选）②选择目标容器。选项：--量 <值>（默认 全部/未知）。提交 committed。写入 transfer 事件 + located_in + 量记录。撤销：移除事件与关系。

**取出 `takeout`** — 签名：material(1..n) ← container(1)。选项：--量 <值>。提交 committed。写入位置关系结束/转移事件。撤销：恢复关系。

**混合 `mix`** — 签名：material(2..n) × container(0..1)。提示：①多选物料 ②可选目标容器。提交 committed。写入：开始混合过程（双向缓冲启动，原料标“正在消失”，产物标“正在被创建”）。撤销：撤销过程与标签。

**分件 `split`** — 签名：material|intermediate(1) → 份数 N。提示：①选择要分件的对象 ②输入份数。提交 committed。写入：N 个子对象 + 来源关系；原对象量减或标记未分配。撤销：合并回退。

**开始操作 `start`** — 签名：过程类型 × 参与者(1..n) × 设备(0..1)。提示：①选操作类型 ②多选参与者 ③可选设备。提交 committed。写入：持续过程区间，落在 playhead。撤销：删除过程。

**结束操作 `end`** — 签名：进行中过程(1)。提交 committed。写入：关闭区间右端；出口产物按需创建。撤销：重新打开区间。

**记录测量 `measure`** — 签名：object(1) × 量 × 值。提示：①选对象 ②选量 ③输入值。提交 measured。写入：Measurement + Lock。撤销：移除测量与锁点。

**提问 `ask`** — 签名：object|process(0..n) × 自然语言。提交：不产生事实。写入：Question → Case Preview。撤销：关闭问题。

**回填实测 `record`** — 签名：process|run(1) × 值。提交 measured。写入：实测事件；相关分析标过期。撤销：移除实测。

**新建版本 `fork`** — 签名：名称。提交 committed。写入：Recipe 版本分叉（在 playhead）。撤销：删除未引用的版本。

**召唤泳道 `lanes`** — 签名：object(2..5)。只读临时视图。不写入事实。撤销：Esc 即消失。

**导出手册 `export`** — 签名：run(1) × 格式。提交：不产生事实。写入：手册文件到 exports/。

**新建方法 `defmethod`** — 签名：名称 × 指标(0..n)。提交 declared。写入：MethodDef（semantics 可为 null）。撤销：删除方法。

### B.4.6 CMD 语法与行为

- 任何字符输入默认进入 CMD（Rhino 式直接打字，无需先聚焦）；
- verb-first：`倒入` → 提示“选择物料”→ 点选/多选 → 提示“选择容器”→ 点选 → Enter 提交；
- 全内联亦可：`倒入 面粉 搅拌碗`、`分件 面团 6`；
- Tab 补全谓语与对象名；`help <谓语>` 显示签名、提示与示例；↑↓ 历史；Esc 取消；Enter 提交；
- picking 中点选现场对象填充当前宾语槽位，角色不符时状态栏红字提示需要哪个角色；
- 回显：`CakeCAD> …` / `OK · <结果>` / 红字错误+建议。

## B.5 视觉语言

深色工程实验室外壳 × 纸质便签对象：外壳是仪器，对象是侦探板上的证物。

色板：背景 `#080909`、画布 `#0D0E0E`、面板 `#111211`、浮层 `#171817`、分割线 `#292522`、弱边框 `#3A3029`；主琥珀 `#C66B2C`、高亮橙 `#F08A3C`（playhead/hover/关键帧）、暗铜 `#704022`、金 `#D99A42`（成功）、深红 `#A34232`（错误）、冷灰 `#747574`。强调色克制：只给选中、活跃命令、playhead、关键按钮。

字体：界面与数值等宽（JetBrains Mono/IBM Plex Mono），中文 Noto Sans SC；文案短、工程化、低情绪；禁止营销文案。形体：细边框、少阴影、圆角 2–6px、光效只表达状态。

颜色语义三层：文字标题为主、色条为辅；用户改色只是样式；分析派生外观用独立徽标/色带并带图例与开关。

## B.6 现场：代理物、FFD 与传记

- **本体裁决（已拍板，L046）**：物料与性质逻辑的本体 = 标签层（对象 + 稀疏标签 + 自然语言声明 + 命名部件）。布料/海绵网格不作为本体保留；网格只允许作为 Analysis 算例内部的临时表示存在，算例输出以值/区间/标签回到事实底座。几何层 = 草稿/演示：可孤立存在，或约束于一个标签作其下游可视化；不直接参与物料流，不承载身份与账本。

- 当前纵切用 **2D 语义代理画布**（HTML/SVG）；3D 现场（Three.js/R3F）在后续环引入。数据结构对 2D/2.5D/3D 中立。
- **3D 是待验证假设**：它只对四件事不可替代（难言的空间语义、剖面、空间基准操作、现场感）。降级预案：隐藏 3D 后事件日志完整、溯源工作、分析能跑、MD+脊柱+Header 能记全流程——四问全"是"才安全。
- **资产策略**：原语 + 标签牌 + 可选照片贴图；单资产制作超 15 分钟就退回原语。
- **FFD 三维便签**（3D 环）：lattice 控制笼拖拽变形，形状永久保持、不回弹不下落，悬空穿模合法；要"布料感"就一次性松弛后烘焙。**零运行时物理；变形结果只是展示草稿，不反写物料事实。**
- **代理物形态**：便签卡片（现实现）vs 实验容器剪影（Chemist 式，L018）——未决，体验后定。
- **对象传记**：带来源的派生视图；每条重要陈述可回查；用户不能覆盖正文，只能改底层事实或追加 Note。

## B.7 分析算例的界面

分析从**提问**开始，不从按钮开始。

- 入口：右键"提问"/"快速估算"、CMD、Header 警告点。
- 流程：自然语言提问 → 编译为 Question → Agent/系统提议 AnalysisCase → **Case Preview 闸门**（显示用哪些输入、哪些是 guess、忽略什么、模型与适用域）→ 用户确认 → 确定性计算 → 结果卡。
- 结果呈现：区间而非伪精度；同时显示"结果不确定度"与"模型适用可信度"两个数；五级置信 Verified/Supported/Extrapolated/Speculative/Unknown——**Unknown 是合法答案**。
- 破坏性算例进 Analysis 沙盒，不触碰 Run。
- 结果卡落在 Inspector/召唤区，存 `analyses/`，绑定版本、时间与依赖；输入变了标过期。

## B.8 备份与版本的界面

- **Recipe（设计基线）**：可版本、可分支、可 diff；分支图按需召唤（B 键/抽屉"版本"页），平时不占屏。
- **Run（一次执行）**：append-only 事件流，永不分支；可中止（中止即事实）；结束后可后验回填实测。
- **备份**：项目文件是 `.cakecad` 目录（C.10），天然可复制、可 Git；保存即 Recipe 快照 + Run 归档，都是不可变的。
- "改主意" = 新 Recipe 版本或新 Run；不是改历史。

## B.9 首个纵切：曲奇

**目标**：验证"随便写摆 → 提升为时间化事实 → 按需分析 → 分支不污染 → 导出手册"的完整闭环。

**动作序列**：

1. MD 写三行不完整笔记（不产生事实）；
2. 现场摆出原料与设备（sketch）；
3. 多选干料 → "混合" → 时间脊柱出现过程区间（playhead 处）；
4. 拖播放头经过过程 → Header 显示"料理机运转中，内含…"；中途"倒入黄油"；
5. 结束混合 → 出口自动生成 `mixture_01`（可改名"曲奇面团"）；
6. "分件 6" → 子对象带来源；摆盘、入炉；
7. "开始操作：烘烤"，结束条件"边缘上色、中心偏软"；生→熟同一 ID；
8. "快速估算" → Case Preview → 观察窗口区间；
9. T 键召唤泳道：烤箱 vs 面团重叠对照；
10. 回填实测"13 分钟、出炉 80g" → 显示理论/实测差异；
11. 一键导出操作手册。

**里程碑门**：M1 交互内核（已完成）→ M2 曲奇业务闭环 → M3 分析与手册。每里程碑体验后回本文件，不夹塞零散改动。

**失败条件**：Markdown 被当脚本执行；视图各存一份事实互相同步；拖入容器自动等同消耗；靠近容器强制弹窗；强迫精确时间；未知质量阻止继续；熟曲奇凭空入场；分析覆盖实测；必须先搭节点图；为演示建完整 3D 资产库；Run 被改写。

# C. 概念模型

## C.1 三层骨架：Recipe / Run / Analysis

```text
Recipe（设计基线）  可版本、可分支、可 diff、可 merge    像图纸
   │ 实例化
Run（一次实际执行） append-only 事件流，永不分支        像试车
   │ 引用
Analysis（分析）    引用 Recipe + Run，可复算、可沙盒    像试后报告
```

它消解了旧分支模型的全部纠结：分支同步=Recipe 层成熟 diff/merge；反事实=Analysis 沙盒不给伪事实；实测覆盖=Run 无写权限；备份=两者天然不可变；分支选类型=不需要（设计分支与推演情景天然分层）。

## C.2 实体总表

| 实体 | 是什么 | 关键规则 |
|---|---|---|
| Project | 一个 .cakecad 项目包 | 含以下全部 |
| Note | Markdown 底稿 | 原文永不改写；锚点另存 |
| Object | 有身份可引用的东西 | 物料/介质/载体/工具/设备/容器/组合体/Region/Pile/Stub/变量/副产物 |
| Event | 某时刻的变化或记录 | append-only；带状态 sketch/planned/performed/measured |
| Relation | 对象间带有效期的联系 | 带承诺强度 observed/declared/inferred/committed |
| ProcessInterval | 持续过程 | 一等公民；inputs 多个带入口时间，outputs 列表，combine 设 primaryOutput；承载中途事件 |
| TimePoint/Range | 时间 | 精确/区间/仅顺序/未知/开放结束；绝不默认吸附 |
| ValueCell | 值单元 | 值+单位+原文+来源+策略+锁点+不确定度+stale+overrideOf |
| Measurement | 实测 | 不可被模型覆盖 |
| Variable | PLM↔CAE 的桥 | 绑定对象字段/实测/表达式/自由量；可拟合、带适用域 |
| Recipe / Run / Analysis | 三层骨架 | 见 C.1 |
| Question | 一次提问 | 一等公民；分析的入口 |
| ModelCapsule | 模型胶囊 | 带适用域、证据、成本、外推策略 |
| MethodDef | 用户自造方法 | 任意命名、任意指标；semantics 可为 null |
| Lock | 自动传播的边界 | 实测/已执行/已发布/手动/导入/算例输入 |
| Conflict | 不一致记录 | 不等于错误 |

## C.3 对象身份与过程期模型（双向缓冲）

对象是扁平的、带身份的；状态、阶段、是否正在被消耗/创建，一律用稀疏标签与关系挂载，不现场套更高级对象。唯一的高阶实体是过程（时间区间），它只引用对象，不包裹对象。

- **一进一**（生→熟曲奇）：同一 ID，状态片段区分。
- **一分多**：子对象带来源关系；原对象保留历史。
- **多进一（混合）= 双向缓冲**：
  - 过程 P 是一等实体，有 start/end，inputs 多个且各自带入口时间（途中可加黄油）；
  - 进入 [start,end] 后：已入口原料带标签“正在消失于 P”；产物带标签“正在被创建于 P”（暂定态，自动临时名，可后改）；
  - 过程期内的查询/引用默认指向“正在被创建的”产物，原料仍可查；
  - P.end：产物 → 已创建/存在；原料 → 已消耗/结束（未耗尽保留）；
  - 中止：产物 → 创建中止（记录，不删除）；原料 → 未消耗/退回。
  - 过程中产物的量可推导（已入口原料之和），不是零信息对象。
- **产物唯一性**：仅对 combine/mix 主产物唯一；separate/clarify 可多产物。故 outputs 为列表，combine 设 `primaryOutput`。
- **过程定义于谁**：过程是独立实体，不定义于产物也不定义于原料（存在无产物过程如预热、多产物过程如分蛋）。combine 类用 `primaryOutput` 做命名/锚点（“打面”≈“做面团”），是便利不是结构要求。
- **命名由引用产生**：用户不引用就不需要正式名字；暂定态自动临时名，手动负担零到一次点击。
- 用户可覆盖任何默认判据，覆盖留痕。

## C.4 提交规则

空间动作默认只产生 sketch。四影响维度独立：spatial / material / state / process。提交状态：`sketch → declared → committed → measured`。提升通过谓语命令完成。

## C.5 事件日志与单向物化

```text
事件日志（唯一真相，只追加）
  → 时段注册表（物化索引，可随时从日志重建，非第二份真相）
  → 视图（Header / 现场 / 脊柱 / 召唤区，皆廉价投影）
```

方向单向：注册表坏了随时重算，日志永远不动。黑客松规模下 `stateAt(t)` 每次从头 fold 即可。

## C.6 不守恒分类

未分配质量 / 已知损耗 / 未知损耗 / 测量残差 / 计划余量 / 人工覆盖差异（ValueCell 的 overrideOf 直接算出）。有依据的剩余量不是"不守恒"。

## C.7 沉默审计员（永远在跑，默认不说话）

1. **接触留痕**：对象进入粘性物/液体范围又离开 → 生成 `possibly_contacted` 候选关系 → 极小灰点，点开才有[确认无转移/声明沾附/忽略]；
2. **质量账本**：每个混合物随时有理论输入 vs 已声明输出，差额不报错但永远可查；
3. **拓扑最低检查**：引用不存在的对象=唯一硬错误；产物早于全部原料=黄色标记。

漏掉的东西全留痕，只是默认不吵你。

## C.8 七种"不知道"

| 类型 | 例子 | 表示 | 下游行为 |
|---|---|---|---|
| 值未知 | 挤了多少奶油 | value:null, knowable:true | 可补测，灰点提示 |
| 存在未知 | 碗壁还有残留吗 | 候选对象，低置信 | 只影响守恒审计 |
| 时间未知 | 什么时候分的团 | order_only | 排程分析拒绝，其余照常 |
| 因果未知 | 为什么摊开了 | 未解决 Question | 触发后验诊断 |
| 适用性未知 | 这模型能用吗 | validDomain 越界 | 降置信，标外推 |
| 身份未知 | 这是昨天那碗吗 | 弱绑定 | 溯源链标断点 |
| 原则不可知 | 杏仁粉的"真实完整物性" | semantics:null | 中性图标，各分析自行声明假设 |

## C.9 调和 Reconcile

暂停约束 → 自由编辑 → 恢复一致。流程：算影响范围 → 断点 → 锁点 → 可调整变量 → 可接受差异 → 候选方案 → 显示将改什么 → 用户确认 → 写入新事件或新版本。

## C.10 复用与项目文件

两种引入正交：物料流转（消耗批次）与配方实例化（跨时间跨项目复制组成，不消耗原批次）。

项目文件 `.cakecad/` 目录（可 zip）：

```text
manifest.json
notes/        main.md（原文永不改写）+ anchors.json
recipes/      基线 + 版本历史 + 分支
runs/         run_xxx/events.jsonl（append-only）+ measurements.jsonl + snapshots/（可删可重建）
objects/      project.json + global.json（酵种/炸油/模具跨项目）
variables.json  methods.json（含用户自造方法）
analyses/     case.json（输入快照+假设）+ result.json
geometry/     proxies.json + baked/*.glb
exports/      manual_xxx.md
```

JSONL 使追加=文件追加，天然 Git 友好。外部引用默认锁定版本、手动更新、可无环快照。

## C.11 CAD / PLM / CAE / CAM

不共享同一个"完整对象"：CAD=形状位置，PLM=身份来源批次，CAE=材料边界，CAM=路径工序。从同一事实底座按需切片。不对齐不是失败。

## C.12 节点图定位

节点图是深层结构视图（依赖/分析管道/调试），读同一事实底座，非必经入口。不继承 chat2 模型。

## C.13 参考数据模型（暂不拘束实现）

方向性参考，实现可偏离但语义不变：`Object{ id, name, kind, roles, quantity?, state?, fitness?, processability?, geometry?, lifecycle, scope? }`；`Event{ id, runId, time, seq, type, participants, effects{spatial?,material?,state?,process?}, label?, status, source, anchors? }`；事件类型内核很小：`create/transfer/combine/separate/place/process + measure/observe/annotate/name + process_start/end/pause/intervene/resume/abort + bind/unbind`；`combine` 细分 mix/assemble/coat/embed/layer/adhere/juxtapose，只有 mix 让输入失去独立身份。

# D. 分析与仿真

## D.1 懒仿真

不提就不仿真；无数据可以沉默；单点数据只声明不拟合；多点才插值；模型带来源、适用域、不确定度；只在所需局部闭合。

## D.2 分析分类

使用方式（为什么算）：快速计算 / 先验建议 / 过程指导 / 后验检查 / 反事实情景。
属性矩阵（另记）：对象 object/process/history/scenario × 时间 static/dynamic × 方向 predictive/diagnostic × 重量 quick/local/heavy × 破坏 read_only/non_destructive/destructive。

## D.3 模型融合

机理基线 + 数据修正残差（ŷ = y_physics + r_data，首选）；机理生成特征 + 小模型；多专家 + 规则门控。不做加权平均。必须分开显示结果不确定度与模型适用可信度。

## D.4 Case Preview（防幻觉闸门）

任何分析运行前显示：将使用的输入（✓ 已确认 / ? 假设）、将忽略的内容、模型与依据、适用域检查。用户可补参数、改假设、接受默认、跳过未知、取消。

## D.5 破坏性判定

只读 → 直接跑；非破坏（临时补参不写事实）→ 直接跑；破坏性（重分配质量/改状态/强制守恒）→ 进 Analysis 沙盒。沙盒是 Analysis 的属性，不是用户要选的分支类型。

## D.6 AI Agent 边界

能做：读现场提议 AnalysisCase、检索模型胶囊与文献（附来源）、从 MD 提取候选项（待确认）、把结果翻译成人话+因果链、猜缺失参数（标 guess）、按标签接线。
绝不能做：直接写事实层（必须过 Zod + 用户确认）、改 measured/executed 锁点、自行断言物理结论、隐式补齐、静默改历史。

**Agent 生成算例，不生成结论。**几何与数值全部确定性计算。无网络时本地功能完整。
